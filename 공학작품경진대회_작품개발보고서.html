한 줄 요약

구형 데스크톱 에이전트 의존성과 별도 서버 게이트웨이 분리안을 모두 제거하고, omp 18.16.0 에이전트 런타임을 Node 호스트(UI + bridge + 인프로세스 게이트웨이 라이브러리)가 자식 프로세스로 기동하는 무설정 플랫폼 VAYEX다. 호스트는 Node.js 기반 로컬 실행 환경으로서 자체 루프백 리스너에서 OpenAI 호환 추론 엔드포인트를 서비스하고, 자식은 그 /v1을 HTTP로 호출하며, 밖으로 나가는 업스트림 요청은 호스트가 수행한다. 로컬 임베딩 기반 FTS5+벡터 하이브리드 메모리(app/memory), Git 없는 스냅샷·diff 확인·되돌리기 및 자동 검증 DX 계층(app/dx)을 완비했다. UI는 7종 테마 스튜디오, 텍스트 수직 래핑 버그를 제거한 3모드 인스펙터, 완료 한 줄 작업 일지와 diff 분리, 4종 세션 산출물 문서 생성기(HTML + 헤드리스 PDF), 전송 전 개인정보 보호 가드, 디자인 모드 웹 미리보기, 하단 상태 표시줄을 제공한다. 백그라운드 작업(제목 생성·진행 요약·다이제스트)은 외부 LLM 호출 없이 결정론적 규칙 계층(Zero LLM)과 45초 타임아웃의 관측 가능 워치독으로 완결된다.

개요 및 배경
AI 코딩 에이전트는 학부 과제와 바이브 코딩의 핵심 도구가 되었으나, 개발자가 체감하는 진입 장벽은 모델의 이론적 파라미터 크기가 아니라 비용·환경·신뢰다. 본 프로젝트는 사용자 PC에서 설정 없이 즉시 구동되는 로컬 통합 하네스를 목표로 한다.
1.1 개발 배경 — 개발자와 바이브 코더의 현실적 페인 포인트
01

높은 AI 도구 이용 비용

월 20달러(약 3만 원) 구독료는 개인 사용자에게 부담스러운 고정 지출이다. 코드베이스를 탐색할 때마다 누적되는 클라우드 토큰 요금은 반복 디버깅 중 AI 활용을 위축시킨다.

02

AI 도구의 복잡한 환경 설정

거대한 데스크톱 Electron 앱이나 복잡한 프레임워크를 번들링하는 대신, 경량 Node 호스트가 UI와 추론 엔드포인트를 직접 서비스하고 에이전트 런타임만 자식 프로세스로 기동하여, 별도로 기동해야 하는 서버가 없는 환경을 구성한다.

03

AI가 수정한 코드를 확인하기 어렵다

바이브 코딩에서는 자연어 요청 한 번에 여러 파일이 변경된다. 코드를 깊이 읽기 어려운 사용자일수록 무엇이 변경되었는지, 되돌릴지, 시험이 통과하는지를 한 화면에서 확인할 수 있어야 한다. 본 작품의 UI(바엑스)는 텍스트 수직 래핑 글자깨짐을 제거한 3모드 인스펙터, AI 작업 일지, 파일 변경 diff 보기와 되돌리기를 제공한다.

04

동의 없는 소스코드 전송 우려

작업 중인 코드가 사용자 모르게 외부 클라우드로 전송되는 것은 보안상 부담이다. 클라우드 경로는 대화마다 새로 받은 명시 동의가 있어야 열리고, 동의 상태는 대화 단위로 초기화된다.

1.2 개발 목적과 Zero-Config 철학
설정 제로 (Zero-Config)
launch.cmd 더블클릭으로 저장소 .omp-runtime\에 이미 있는 Bun/omp를 실행한다. 설치·내려받기 단계가 없고, 런타임이 없으면 launch_failed로 멈춘다.
로컬 하네스 = 호스트 + 자식
Node.js 기반 로컬 실행 환경(app/server.mjs)과 자식 에이전트(omp 18.16.0, stdio JSON). 별도 게이트웨이 서버 프로세스는 없다.
클라우드 동의와 전송 가드
클라우드 경로는 대화별 명시 동의가 있어야 허용되며, 위조·미동의 헤더는 403 consent_required로 차단된다. 전송 가드는 서버에서 동작한다.
대회 부스 시연 안정성
상시 재생 통합 영상과 관람객별 2~3분 현장 실작업 세션으로 나눠 운영한다. 기본 실행은 번들 스텁(demo-chat) 오프라인 경로라 현장 네트워크가 실패 요인이 되지 않는다.
목표: "코딩의 항로를 스스로 열다"라는 슬로건 아래, 사용자 PC에서 로컬 하네스(호스트 + Bun 자식)가 즉시 구동되어, 별도 서버 기동이나 런타임 설치 없이 자연어 요청 → 작업 일지 확인 → 변경 내역 확인과 되돌리기로 이어지는 코딩 흐름에 전념할 수 있는 단일 플랫폼 '바엑스(VAYEX)'를 제공하는 것.

4.3.1 무엇을 검사하고 무엇을 남기는가

검사 범위와 판정

정규식 탐지에 체크섬 검증, 엔트로피 판정, 토큰 효율 판정을 더해 판단한다. 확인된 자격증명이 남아 있으면 업스트림 호출 전에 HTTP 422로 거절하고, 가명 처리된 본문은 와이어로 나가기 전에 다시 검증한다. 모든 클라우드 라우트에 같은 규칙이 적용되며, 동의 여부와 가명 처리 여부는 하나의 값으로 합치지 않고 따로 기록한다.

원문 노출 금지: 원문 값은 로그, 이벤트, 문서, 화면 어디에도 남지 않는다. 화면에는 유형·조치·전송 여부만 한 줄로 남는다.

구문에 맞춘 두 가지 가명 형태

본문에는 [PERSON_1] 형태를, 코드 식별자가 들어가는 자리에는 __PII_PERSON_1__ 형태를 쓴다. 후자는 식별자로 유효한 문자만 남기므로 가명 처리된 코드도 그대로 컴파일된다. 가명은 요청 범위 안에서만 유효하고, 복원 매핑은 전송 본문에 실리지 않는다.

경계: 가드는 전송 전에 동작한다. 사용자가 대화에 직접 입력한 값을 복원하는 기능이 아니라, 외부로 전송되는 시점에 차단하고 가명 처리하는 기능이다.

01
사용자 진입 비용 감소
기본 경로는 이미 있는 런타임을 쓰고 아무것도 내려받지 않는다. 상시 영상과 2~3분 세션으로 짧은 체류에서도 구조와 한계를 전달한다. 절감률 같은 정량 주장은 하지 않는다.
02
코드 자산 보안과 프라이버시
외부 클라우드로 소스코드를 보내지 않는 것이 기본값이다. 클라우드 경로는 화면의 동의 토글로 명시 동의를 받기 전에는 만들어지지 않고, 전송 전 개인정보 가드가 자격증명을 차단하며, 원문 값은 화면에 남지 않는다.
03
운용 신뢰성 (부분)
무리한 실행을 막는 결정론적 정책 게이트와 원장 기록기가 구현되고 검증기 계약은 프로브로 확인했으나, 아직 하네스 런타임에 배선되지 않았다. "런타임에서 환각을 자동 차단한다"고 시연하지 않는다.

원격 워커 모델 미관측: 벤치마크 실측을 완료했으나(§5.2) VAYEX의 실행별 실제 라우팅 대상은 응답 본문이 아니라 게이트웨이 관리 API로 사후 회수해야 했다. 게이트웨이가 호출별 USD를 보고하지 않으므로 비용은 회수한 라우팅 대상의 공시 단가 × 측정 토큰으로 계산한 값이며 실제 청구서와 같은 값이 아니다. 과금이 관측되지 않는 턴은 0으로 채우지 않고 비용 미집계(원격 워커 과금 미노출)로 표시한다. 과거 시뮬레이션의 11.2%·38.1%는 가상 시뮬레이션 가정치이며 실측 벤치마크 완결로 공식 폐기되었다.
2
백그라운드 요약의 규칙 계층 의존: 세션 제목·진행 요약·다이제스트는 외부 LLM을 호출하지 않고 정규식 및 규칙 계층으로 구동된다. 더 나은 요약을 위한 소형 모델 후보가 레지스트리에 선언되어 있으나 측정 환경에는 가중치가 설치되어 있지 않아 후보의 성능·품질은 미측정이다. 워치독으로 턴 멈춤을 감시하나 복잡한 자연어 요약의 정밀도 평가는 후속 과제다.
3
독립 데스크톱 패키징 미완: 단일 웹 작업공간 UI(app/public/)와 브라우저 회귀 51/51 통과는 확인했으나, 별도의 단독 설치형 실행 파일(Executable Bundling) 구성은 후속 작업이다.
4
게이트웨이 보안 재검토·실공급자 검증 미완: 게이트웨이 라이브러리 시험 148/148 통과는 스텁 대상이며, 외부 상용 공급자 연동 시의 실제 API 호출과 외부 보안 수용은 미검증이다. 프라이버시 가드의 도우미 모델 단계도 가중치가 설치되지 않아 미측정이며, 안전의 하한은 정규식·체크섬 계층이 보장한다.
5
경계면 미봉합: 턴별 플래너는 검증되었으나 하네스 턴 이벤트에 배선되지 않았다. 규칙 수는 구현체에 따라 다르다 — Python engine/decision_planner.py의 validate_turn_plan이 V-01~V-09(V-09 스킬 부분집합), JS gateway/lib/turn-plan.mjs의 validateTurnPlan이 V-01~V-08이다. 20 KB 디스크 스필 모듈(무손실 복구 확인)은 coreArgs에 등록되었으나 실추론 대상 절감 크기는 미측정이다. prompt_cache_key와 --extension은 독립 검토 후 철회되어 제품 경로에 없다.
8. 결론

본 작품은 omp 18.16.0 에이전트 런타임을 Node 호스트가 자식 프로세스로 기동하고, 게이트웨이는 그 호스트가 라이브러리로 인프로세스 임포트하는 로컬 하네스 기반의 사용자용 무설정 AI 코딩 플랫폼 '바엑스(VAYEX)'이다. "코딩의 항로를 스스로 열다"라는 슬로건 아래, 텍스트 수직 래핑 버그를 제거한 3모드 인스펙터, 7종 테마 스튜디오, 완료 한 줄 작업 일지와 diff 분리, 전송 전 프라이버시 가드, 4종 세션 산출물 문서 생성기(HTML+헤드리스 PDF)를 결합했다. 별도 게이트웨이 서버 프로세스는 폐기된 구성이며 현재 요청 경로에 없다.

과장된 벤치마크 수치나 조작된 결과를 배제하고, 전 계층 시험 기록(앱 계층 154/154, 게이트웨이 148/148, 장기 기억 42/42, 브라우저 회귀 51/51 — 실패 0)과 실제 동작하는 계측 경로, 그리고 아직 구현되지 않은 항목(동적 조정 런타임 미배선, 실공급자 추론 미검증)을 분리해 제시한다. 이 작품이 현재 주장하는 것은 두 실행 단위(호스트와 그 자식인 에이전트 런타임)로 이루어진 로컬 하네스의 구조와 규약, 그리고 그 규약의 어디까지가 실행으로 확인되었는가이며, 완성된 안전성이나 엔드투엔드 통합이 아니다.
