1. 개요 및 핵심 설계 원칙

본 문서는 대규모 언어모델(LLM) 기반의 차세대 자율형 소프트웨어 엔지니어링 에이전트 플랫폼의 시스템 아키텍처와 세부 컴포넌트 명세를 규정한다. 본 플랫폼은 단일 플래그십 모델 의존에 따른 운영비 폭증과 컨텍스트 팽창 문제를 해결하기 위해 클라이언트-서버 분리형 구조와 적응형 이기종 모델 라우팅을 핵심 아키텍처로 채택한다.

4대 핵심 설계 원칙: 1) 실행권-중계권의 물리적 분리: 로컬 샌드박스가 코드 실행을 독점하고, 중앙 서버는 순수 API 중계 및 메타데이터 관리만 수행.
2) 작업 지능 요구별 최적 모델 배치: 고지능 설계는 플래그십, 일반 코딩은 가성비 중급 모델, 단위 테스트/린트는 초저가 모델을 배치.
3) 결정론적 실행 통제: 계획 생성은 LLM이 하되, 동시성·예산·타임아웃·롤백은 로컬 오케스트레이터가 강력하게 통제.
4) 프라이버시 우선(Zero-Retention): 기본값으로 데이터 학습 비동의 경로를 강제하고 적격 경로 부재 시 원천 차단.

2. 시스템 아키텍처 설계 (2-Tier 분리 구조)

[로컬 계층] DeepSeek Harness 기반 튜닝 클라이언트

  • 실행 제어권 독점: 로컬 파일 수정 및 터미널 테스트 실행 전담
  • Desktop GUI: 원클릭 간편 모드 / 전문가용 고급 설정 모드
  • Local Orchestrator: Plan Validator, DAG Scheduler, Budget Controller, Workspace Manager, Checkpoint Store
  • Context & Storage: AST 파서 기반 심볼 추출, SQLite + FTS5 전문 검색(무임베딩 고속 메모리), 100만 토큰급 계층 요약 압축

[서버 계층] OpenCodex 기반 경량 게이트웨이

  • 무상태 경량 프록시: 코드 비실행, SSE 양방향 스트리밍 중계
  • 보안 및 키 금고: 공급자 마스터 API Key 서버 측 암호화 보관
  • Privacy Enforcement: Zero Data Retention 경로 엄격 강제
  • Model Intelligence Registry: 인덱스 40점 이상 필터링, 최신 단가·벤치마크·후기 수집 및 11대 전문 역할 카테고리화

  • 데이터 수집원: Artificial Analysis Intelligence Index, 공식 API 사양 및 컨텍스트 윈도우, Reddit/GitHub 실사용 평판, 제공자별 입력/출력/캐시 단가.
  • 지능 필터링 기준: Intelligence Index 40점 이상을 범용 후보로 하되, 40점 미만이라도 정규식·단순 린트 등 특정 전문 영역에서 가성비가 입증되면 예외 등록. 점수 미보유 모델은 미평가 후보로 격리.
  • 11대 전문 역할 분류 체계:

3.2 결정론적 로컬 DAG 오케스트레이터 및 3단계 자율 복구

계획 생성은 확률적(Stochastic) LLM이 수행하지만, 실제 실행과 복구는 로컬의 결정론적(Deterministic) 오케스트레이터가 엄격하게 통제한다.

  • Simple-Task Fast-Path: 단일 파일 수정 등 단순 작업은 Decision API 호출을 생략하고 규칙 기반으로 저비용 단일 모델 직행.
  • DAG Scheduler: 위상 정렬(Topological Sort)을 통해 선행 의존성이 해소된 노드를 병렬 실행 큐에 자동 디스패치.
  • 3단계 자율 복구 프로토콜:
    1. 1차 복구 (Local Retry): 단위 테스트 실패 시 에러 로그를 주입하여 동일 모델이 1회 국소 수정.
    2. 2차 복구 (Model Escalation): 실패 지속 시 상위 티어 고지능 모델로 서브에이전트를 동적 승격하여 재작성.
    3. 3차 복구 (Local Replanning): 승격 실패 시 Planning Engine에 해당 노드 하위 DAG 재계획 요청.
    4. 최종 안전망 (SQLite Rollback): 3회 연속 실패 시 스냅샷을 통해 원본 코드로 즉각 롤백하고 사용자에게 리포트.

5. 10대 정량 검증 지표 및 4개 군 대조 평가 방법론

5.1 4개 대조 비교군 설계

실험군 에이전트 구성 모델 및 라우팅 전략 평가 목적
군 A단일 에이전트플래그십 고정 (GPT-6.1-SOL)기존 표준 상용 코딩 방식 기준선
군 B단일 에이전트작업 단계별 모델 전환단일 에이전트 환경의 라우팅 효과 측정
군 C멀티 에이전트모든 에이전트에 동일 플래그십 배정단순 멀티에이전트의 비용 팽창 실측
군 D (제안)적응형 이기종 멀티지능 요구별 다중 모델 적재적소 분배품질 유지 및 비용·시간 최적화 입증

5.2 10대 정량 평가 지표

평가 지표 측정 내용 및 실측 방법
1. 작업 성공률 (%)사전 정의된 동일 코딩 테스트 케이스 및 린트 통과율
2. 전체 완료 시간 (s)프롬프트 입력부터 최종 검증 통과까지 총 소요 시간 (Latency)
3. 실제 총 API 비용 ($)게이트웨이에서 공급자에게 실제 결제 청구된 API 금액
4. 성공 작업당 비용 ($)총 발생 비용 / 성공 작업 수 ($/Success) — 본 작품의 핵심 경제성 지표
5. 세부 토큰 사용량입력 토큰, 출력 토큰, Prompt Cache 적중 토큰 세부 구분 집계
6. 결정/계획 오버헤드Decision/Planning 호출에 소요된 시간 및 비용의 전체 대비 비중 (%)
7. 서브에이전트 효율병렬 처리에 따른 시간 단축 배율 및 작업 분할·조율 오버헤드 측정
8. 실패 복구율1차 검증 실패 후 국소 재계획 및 상위 모델 승격을 통한 최종 회복 성공 횟수
9. 사용자 개입 횟수작업 진행 중 사용자가 수동으로 개입하거나 설정을 조정한 횟수
10. 정책 준수율 (100%)데이터 학습 비동의 환경에서 미승인 경로로의 유출 차단율 (100% 필수)
