# 사용자·바이브 코더 편의도구를 위한 오픈소스 벤치마크 및 UI 설계 조사서

> **문서 지위 및 설계 원칙**
> - 본 문서는 사용자 및 바이브 코더(vibe-coder)의 개발 편의성을 높이기 위한 오픈소스 컴포넌트들을 조사·비교·평가한 **설계 조사서**이다. 제품 코드나 런타임 구현이 아니다.
> - 본 프로젝트의 기존 애플리케이션(`40_AI보고서/app/`) 및 시스템 게이트웨이는 수정하지 않으며, 향후 프론트엔드 작업자(`front-worker`)가 UI를 확장할 때 참고할 수 있는 기술적 사실과 라이선스 근거를 정리한다.
> - "100% 동일한 VS Code 언어 서비스", "지연 시간 0", "60fps 보장", "무부하" 등 입증되지 않은 마케팅성 표현이나 성능 단언을 엄격히 배제하고, 실제 저장소의 라이선스 파일, 패키지 구성, 의존성 관계, 확인된 웹사이트 관측 사실에 근거하여 기술한다.

## 1. 배경 및 문제 정의

개발자 및 자연어 프롬프트 중심으로 작업하는 바이브 코더는 터미널 로그만으로 에이전트의 내부 실행 상태를 파악하는 데 어려움을 겪는다.
이를 개선하기 위해 검토해야 하는 주요 편의 기능은 다음과 같다:
1. **코드 및 변경 사항(Diff) 시각화**: 에이전트가 생성하거나 수정한 파일의 변경 내역 확인 및 되돌리기. 파일 변경 적용에는 별도 승인 단계를 두지 않는다.
2. **프로젝트 트리 및 구조 파악**: 프로젝트 파일 목록 및 모듈 구성 확인.
3. **도구 실행 추적 및 계획 확인(Tool Trace / Agent Plan Dock)**: 도구 호출 파라미터, 실행 결과, Todo 진행 상태 열람.
4. **코드 편집 및 미리보기**: 웹 브라우저 내 경량 코드 열람/편집.
5. **접근성 및 단일 통합 UI**: 복잡한 빌드 툴체인 도입 부담을 최소화한 사용자 인터페이스 구성.

## 3. 기능 영역별 후보 오픈소스 프로젝트 조사 및 검증

### 3.1 diff2html (Git Diff 시각화)
- **저장소 및 라이선스**:
  - 저장소: `https://github.com/rtfpessoa/diff2html` (확인 버전 v3.4.48)
  - 라이선스: `https://raw.githubusercontent.com/rtfpessoa/diff2html/master/LICENSE.md` (MIT License, Copyright 2014-2016 Rodrigo Fernandes)
- **특징 및 연동 방식**:
  - Unified diff 포맷 문자열을 파싱하여 Side-by-Side 및 Line-by-Line HTML을 생성.
  - highlight.js와 연계하여 코드 문법 강조 지원.
  - 브라우저 전역 스크립트(`diff2html-ui.min.js`) 또는 번들러 임포트 지원.
- **통합 비용 및 한계**:
  - *연동 비용*: 낮음. 순수 텍스트 diff를 입력받아 DOM에 HTML을 주입하는 구조.
  - *한계*: 읽기 전용 뷰어이며, 인라인 양방향 편집이나 에디터 키바인딩은 지원하지 않음.

### 3.2 @monaco-editor/react (코드 편집 및 검토)
- **저장소 및 라이선스**:
  - 저장소: `https://github.com/suren-atoyan/monaco-react` (확인 버전 v4.7.0, v4.8.0-rc.3)
  - 라이선스: `https://raw.githubusercontent.com/suren-atoyan/monaco-react/master/LICENSE` (MIT License, Copyright 2018 Suren Atoyan)
- **특징 및 연동 방식**:
  - 웹 환경에서 Monaco Editor(VS Code의 에디터 컴포넌트 코어)를 React 컴포넌트로 래핑.
  - CDN 로더(`@monaco-editor/loader`)를 통해 웹 워커와 에디터 리소스를 온디맨드로 로드 가능.
- **통합 비용 및 정확한 사실 구분**:
  - *기능적 사실*: Monaco Editor는 구문 강조, 괄호 매칭, 기본적인 코드 접기 및 미니맵을 제공하지만, **VS Code의 전체 Language Server Protocol(LSP), 복합 확장 프로그램 생태계, 완전한 언어 분석 서비스와 100% 동일하지 않음**. 타입스크립트 외의 고급 언어 분석을 위해서는 별도의 LSP 백엔드나 워커 연결 설정이 요구됨.
  - *연동 비용*: 보통~높음. 번들 크기가 크고 웹 워커 구성이 필요하며, 기존 애플리케이션이 Vanilla JS 스택일 경우 React 의존성 추가 또는 바닐라 Monaco 직접 임포트가 필요함.

### 3.3 react-arborist (가상화 파일 트리)
- **저장소 및 라이선스**:
  - 저장소: `https://github.com/jameskerr/react-arborist` (확인 버전 v3.13.0)
  - 라이선스: `https://raw.githubusercontent.com/jameskerr/react-arborist/main/LICENSE` (MIT License, Copyright 2022 Brim Data)
- **특징 및 연동 방식**:
  - DOM 가상화(Virtualization)를 기반으로 하여 다수의 파일/폴더 노드가 존재할 때 화면에 보이는 영역 위주로 DOM을 생성.
  - 드래그 앤 드롭, 다중 선택, 키보드 네비게이션 제공.
- **통합 비용 및 한계**:
  - *연동 비용*: 보통. 트리 데이터 구조(id, name, children)를 맞추어 상태를 주입해야 함. 고정 높이 렌더링에 최적화되어 있음.
  - *스택 호환*: React 전용 컴포넌트이므로 바닐라 환경에 도입하려면 경량 번들러 또는 대체 바닐라 트리 뷰 검토 필요.

## 4. 기존 앱(`40_AI보고서/app/`) 아키텍처 분석 및 통합 비용

### 4.1 실제 기존 애플리케이션 스택
`40_AI보고서/app/`의 코드를 확인한 결과는 다음과 같다(2026-11-06 확인). **주의: `app/public/`의 프론트엔드는 지금 다른 작업자가 `oh-my-pi-gui` 스타일 3열 레이아웃으로 재작성 중이다.** 따라서 아래 파일 목록과 화면 구조는 확인 시점의 사실이며, 이 문서는 특정 외형이나 고정된 파일 인벤토리를 전제하지 않는다.
- **런타임 및 서버**: Node.js (`package.json` engines `>=26`), `server.mjs`, 내장 WebSocket 브리지(`websocket.mjs`).
- **프론트엔드 구조(확인 시점)**: 순수 바닐라 자바스크립트(ES Modules) + 네이티브 HTML/CSS. 번들러(Vite, Webpack, Rollup)나 UI 프레임워크(React, Vue)는 포함되어 있지 않았다.
- **프로토콜 모델**: `protocol.js`에서 omp `--mode rpc`의 수신 프레임(frame)을 파싱하여 구조화된 `ViewModel`(messages, tools, approvals, route, todos)을 형성함.

### 4.2 모델-이벤트 매핑 및 가공 요구사항
- omp 하네스가 출력하는 원시(raw) NDJSON 스트림은 단순 문자열 diff가 아니며, `protocol.js`(`40_AI보고서/app/public/protocol.js`)에 정의된 바와 같이 다음과 같은 프레임 이벤트로 구성된다:
  - 도구 관련: `tool_execution_start`, `tool_execution_update`, `tool_execution_end` (내부 상태 전이 `toolcall_start`, `toolcall_update`, `toolcall_end`)
  - 메시지 관련: `message_start`, `message_update`, `message_end`
  - 턴 관련: `turn_start`, `turn_end` (참고: `turn_record`는 수신 프레임 이름이 아니며, 클라이언트가 턴 스냅샷을 남길 때 사용하는 `recordTurn` 함수의 내부 객체 형태임)
- 따라서 원시 NDJSON을 `diff2html`에 직접 주입할 수 없으며, **이벤트 매핑 계층**이 필수적이다:
  1. `protocol.js`의 프레임 처리 단계에서 도구 실행 결과(`tool_execution_end`) 수신 시 `frame.result.details.diff` 또는 `frame.result.details.perFileResults[].diff`로부터 unified diff 텍스트를 파싱·추출하여 `ToolFile` 객체로 보관한다.
  2. 추출된 unified diff 문자열만을 선별하여 `Diff2Html.html()` 또는 `Diff2HtmlUI`로 전달해야 정상적인 변경 사항 렌더링이 성립한다.

### 4.3 현실적인 도입 비용 비교 매트릭스

| 프로젝트 | 라이선스 | 패키지/모듈 형태 | 바닐라 앱(`app/`) 통합 비용 | 도입 적합도 판정 |
| :--- | :--- | :--- | :--- | :--- |
| **diff2html** | **MIT** | CDN 단일 JS/CSS 번들 제공 | **매우 낮음**: 번들러 없이 `<script>` 또는 CDN 스크립트 로드 후 즉시 호출 가능. | **최우선 채택 권장** |

## 5. 사용자·바이브 코더를 위한 추천 최소 구성안 (Minimal Selection)

기존 앱의 바닐라 JS 아키텍처를 불필요하게 복잡하게 만들지 않으면서(Zero-bundler 유지), 개발자에게 직관적인 편의를 제공하는 **실제적 최소 스택**:

1. **변경 내역(Diff) 시각화**:
   - **선택**: `diff2html` (CDN 또는 로컬 벤더링 번들)
   - **연동**: `protocol.js`에서 수신된 도구 결과 중 diff 텍스트를 파싱하여 Side-by-Side 뷰로 모달/패널 렌더링.
2. **도구 추적 및 대화 도크 (Conversation Dock)**:
   - **선택**: 네이티브 HTML `<details>` 및 CSS Flex/Grid 기반 자체 레이아웃 (`oh-my-pi-gui`의 레이아웃 배치 참조)
   - **연동**: 외부 무거운 프레임워크 없이 기존 `styles.css`와 `app.js`의 렌더러를 확장하여 입력창 상단에 Todo 상태, 현재 활성 도구, 토큰 사용량 바 표시.
3. **구조도 및 실행 흐름 시각화**:
   - **선택**: `mermaid.js` (ESM CDN 또는 단일 스크립트)
   - **연동**: 에이전트가 마크다운 코드 블록(```mermaid)으로 응답할 때 클라이언트에서 SVG로 즉시 변환.
4. **코드 열람/편집**:
   - 단기: 네이티브 `<textarea>` 또는 경량 바닐라 CodeMirror 6.
   - 장기: 복합 편집 기능 필요 시 바닐라 Monaco 로더 연동.

## 6. 시스템 아키텍처 및 통신 경계 정합성

### 6.1 로컬 하네스(`oh-my-pi 18.16.0`)와의 정합성
- 로컬 하네스는 `--mode rpc` stdio NDJSON 스트림으로 동작하며, `app/server.mjs`의 자식 프로세스 브리지를 통해 WebSocket(`/ws`)으로 클라이언트와 통신한다.
- 클라이언트 측 시각화 컴포넌트는 WebSocket에서 수신한 구조화된 데이터만을 소비하므로 로컬 코어 프로세스에 간섭하지 않는다.

### 6.2 서버 SSH 게이트웨이 경계 정합성
- **통신 경계**: `220.68.175.38:2025`의 SSH 게이트웨이를 경유하며, 루프백 바인딩된 백엔드 서비스(Ollama 등)와는 SSH `direct-tcpip` 터널을 통해서만 접촉한다.
- **클라이언트 비의존성**: 모든 시각화 연산(Diff 파싱, SVG 생성, DOM 조작)은 사용자 랩톱 브라우저 내에서만 완결된다.
- **부하 및 제약 준수**: 서버 평면의 엄격한 제약(포트 포워딩 불가, `nvidia-smi` 비가용, 비-루트 권한, 대역폭 한계)에 일체의 추가 부하나 외부 라이브러리 설치를 요구하지 않는다.

### 6.3 사전 녹화 시연 영상(Competition Video) 요구사항
- 심사에 제출되는 산출물은 랩톱 평면에서의 사전 녹화 영상이다.
- CDN 스크립트를 로컬에 사전 벤더링(예: `app/public/` 아래 벤더 디렉터리)해 둘 경우, 시연 녹화 중 외부 인터넷 연결 실패 위험 없이 완전한 오프라인 환경에서 미려한 Diff 뷰와 다이어그램을 시연할 수 있다. **이 벤더 디렉터리는 계획이며 현재 저장소에 존재하지 않는다**(프론트엔드가 재작성 중이므로 경로도 확정하지 않는다).
