# 공학 작품 경진대회 작품 개발 보고서

> **문서 상태.** 수정본 v4 (2026-11-06 개정). 이 문서는 **실행으로 확인된 사실**, **구현되었으나 실행 기록이 없는 것**, **문서로만 존재하는 설계**, 그리고 **폐기된 계획**을 엄격히 구분해 서술한다. 실행 기록이 없는 성능 수치는 싣지 않는다. 구형 `Mixdog 1.4.5` 데스크톱 에이전트 및 DSH 기반 서술과 더불어, 과거의 **2평면 분리안(로컬 하네스 + 별도 Ubuntu GPU 서버 게이트웨이: RTX 5090, SSH 터널, 8000/8787/4318 포트 분리, 27B/FLUX 배포, GPU 임대/중재)**은 **완전히 폐기/중단(abandoned)**되었다. 현재 시스템의 실행 단위는 **두 개**다. 하나는 **Node 호스트**(`app/server.mjs`: UI + bridge + `app/lib/inference.mjs`가 `gateway/lib/*`를 라이브러리로 임포트하는 게이트웨이)이고, 다른 하나는 그 호스트가 `spawn`으로 띄우는 **에이전트 자식 프로세스**(`omp` 18.16.0, Bun 기반, stdio JSON 스트림)다. 브라우저는 두 실행 단위 밖의 클라이언트이고, 자식은 호스트의 루프백 `/v1`로 들어오며, 업스트림으로 나가는 요청은 호스트가 수행한다. 바뀐 것은 **게이트웨이가 별도 서버 프로세스이기를 그친 것**이며, 시스템 전체가 하나의 OS 프로세스라는 뜻이 아니다.
>
> **표기 규칙.**
> - **구현·실행 검증** = 저장소에 코드가 있고, 실제로 실행해 정상 종료와 출력을 확인했다.
> - **구현·미검증** = 코드는 있으나 저장소 밖 조건(실제 원격 엔드포인트 바인딩, 실제 앱 통합 런타임)에서 엔드투엔드로 실행한 기록이 없다.
> - **설계 전용** = 설계 문서의 규약이며 아직 통합/검증 증거가 없는 설계 단계다.
> - **폐기/중단** = 검토되었으나 현재 제품 요청 경로에서 완전히 배제된 계획.
> - **파라미터** = 코드 상수 또는 설계 문서에 적힌 기준값. **측정 결과가 아니며**, 이 문서는 파라미터를 성능 결과로 읽지 않는다.

## 1. 작품 개요

### 1.1 개발 배경: 학생 엔지니어와 연구실의 현실적 페인 포인트

AI 코딩 에이전트는 학부 과제와 연구실 개발의 핵심 도구가 되었다. 그러나 학생 개발자와 학부 심사위원이 체감하는 현실적 진입 장벽은 모델의 이론적 파라미터 크기가 아니라 **비용·환경·신뢰**다.

1. **학생에게 가혹한 상용 구독료와 토큰 비용 공포.**
   월 20달러(약 3만 원) 구독료는 수입이 없는 대학생에게 학식 4~5끼 가격에 달하는 고정 지출이다. 또한 대규모 캡스톤 프로젝트나 랩실 코드베이스를 탐색할 때마다 누적되는 클라우드 토큰 요금은 밤샘 디버깅 도중 AI 활용을 위축시킨다.
2. **연구실 내 유휴 고성능 GPU와 학생 PC의 단절 (과거 연구 배경):**
   연구실에는 RTX 5090(31.36 GiB VRAM)과 같은 고성능 연산 자원이 존재하지만, 외부 상용 도구는 이를 전혀 활용하지 못한다. 초기에는 이를 SSH 터널로 묶는 2평면 게이트웨이를 검토했으나, 복합 포트 유지보수와 공유 서버 권한 한계로 인해 **요청 경로 내 서버 GPU 연동 계획은 전면 폐기/중단**되었다.
3. **연구실 서버 환경의 현실적 제약과 계획 폐기 사유:**
   실제 연구실 서버는 다수 사용자가 세션을 공유하므로 재부팅이나 sudo 권한 부여가 원천 차단된다. 또한 GPU 드라이버/커널 버전 불일치로 `nvidia-smi`가 동작하지 않고(NVML Error 18), 외부 포트포워딩 불가로 복잡한 SSH 루프백 터널링에 의존해야 했다. 이에 따라 시스템 복잡도를 가중시키는 분리형 서버 게이트웨이 대신, **게이트웨이 모듈을 별도 서버가 아닌 앱 내부 라이브러리로 흡수하고, 에이전트 런타임만 자식 프로세스로 분리하는 아키텍처**로 전환하였다.
4. **설정 지옥(Configuration Hell)과 런타임 거대화 해소:**
   복잡한 프레임워크나 데스크톱 Electron 앱 전체를 번들링하는 대신, 경량 Node 호스트가 UI와 OpenAI 호환 추론 엔드포인트를 직접 서비스하고 에이전트 런타임은 그 호스트가 자식 프로세스로 띄워, 사용자가 띄워야 하는 서버가 하나도 없는 환경으로 진입 장벽을 해소한다.

**본 프로젝트는 분리된 서버 유지보수 부담을 제거하고, Node 호스트와 그 자식인 에이전트 런타임 두 실행 단위로 구성된 로컬 하네스를 제로 컨피그로 제공하는 데 집중한다.**

### 1.2 개발 목적과 Zero-Config 철학

본 프로젝트의 목표는 **"설치 후 실행하면 학생 PC 환경에서 로컬 하네스(호스트 + 에이전트 자식)로 즉시 구동되어, 학생이 모델 다운로드·양자화·VRAM 계산 없이 즉시 코딩에 전념할 수 있는 단일 제품"**을 제공하는 것이다.

- **설정 제로 (Zero-Config):** 하드웨어 프로파일러가 CPU 코어, RAM, GPU VRAM을 측정하여 로컬 실행 티어를 결정론적으로 결정한다.
- **로컬 하네스 = Node 호스트 + 에이전트 자식:** Node 호스트(`app/server.mjs`)가 OpenAI 호환 추론 엔드포인트(`/v1/chat/completions`, `/v1/models`, `/v1/selection`, `/healthz`)를 자체 루프백(기본 4317)에 서비스하고 게이트웨이를 라이브러리로 인프로세스 임포트하며, `omp` 18.16.0 에이전트 런타임은 그 호스트가 `spawn`한 **자식 프로세스**로 실행되어 stdio JSON으로 대화하고 호스트의 `/v1`을 루프백 HTTP로 호출한다. 과거의 별도 서버 게이트웨이 및 SSH 터널링 계획은 폐기되었다.
- **클라우드 동의 및 안전한 연동:** 클라우드 경로는 대화별 명시 동의가 있어야 허용되며, 동의가 없거나 위조된 동의 헤더는 `403 consent_required`로 차단된다. 업스트림은 설정 가능하며 호스트가 직접 아웃바운드로 연결한다. 현재 UI는 기본값으로 클라우드 경로와 동의를 미리 켜 둔 상태이므로, 신규 대화마다 사람에게 동의를 다시 받는 흐름은 **미검증**이다. 전송 가드 자체는 서버에서 동작한다.
- **대회 시연 안정성:** 경진대회는 구두 발표 없이 **부스 전시**로 운영되며, 시연은 노트북 + 24인치 모니터에서 번들 로컬 루프백 스텁(`demo-chat`)을 쓰는 오프라인 라이브 시연이다. 외부 네트워크·서버 연결에 의존하지 않으므로 현장 네트워크 상태가 시연 실패 요인이 되지 않는다. 사전 녹화 영상은 현장 장애 시의 예비 자료일 뿐이며, 시연·심사의 기본 방식이 아니다.

- **폐기된 서버 LLM 호스트 계획:** 과거 검토된 Ollama 0.21.0(연구실 Ubuntu 24.04 호스트 설치, `127.0.0.1:11434`) 기반 서버 LLM 호스트 계획은 **폐기/중단(abandoned)**되었으며 현재 구성요소가 아니다. 기본 업스트림은 번들 로컬 루프백 스텁(`demo-chat`)이고, 실추론을 원할 때는 사용자가 설정한 OpenAI 호환 업스트림을 호스트가 직접 호출한다.
- **런타임 의존의 실제 범위:** Mixdog 데스크톱 에이전트 의존은 제거되었다. 로컬 실행은 `omp`(oh-my-pi) 18.16.0에 의존하며, 그 코어(Bun + `@oh-my-pi/pi-coding-agent`)는 저장소의 `.omp-runtime\`에 이미 놓여 있고 실행 시 내려받지 않는다. DSH(DeepSeek Harness)는 기본 경로가 아니라 `launch.cmd -Runtime dsh`로만 도달하는 **선택 경로**로 남아 있다(핀 `0.2.1-rc.5`, Cordis 패치 오버레이). 그 경로는 PATH에 맞는 `dsh`가 없을 때 `npx`로 패키지를 받을 수 있으므로, "어떠한 런타임 종속성도 없다"고 쓰지 않는다.
- **라이선스 고지 준수:** MIT License를 준수하여 원저작권자 표기 및 라이선스 고지를 제품 패키지 및 문서에 온전히 보존한다.

### 2.2 폐기된 연구실 서버 GPU 연동 계획 (역사적 기록)

과거 연구실 Ubuntu 24.04 서버(RTX 5090 31.36 GiB VRAM, RAM 125 GiB)에 독립 게이트웨이를 띄우고 SSH 루프백 터널(예: 로컬 4318 → 서버 8000, 스텁 8787)을 통해 27B IQ3_S 모델 및 FLUX.1 이미지 백엔드를 연동하고 GPU 중재/임대를 수행하려던 2평면 계획은 **전면 폐기/중단(abandoned)**되었다.

1. **사유**: 서버의 비-root/무재부팅 제약(`nvidia-smi` 비가용 NVML Error 18), 공인 IP 부재로 인한 SSH2025 터널 의존성, 다중 포트 관리 부하, GPU 프로세스 소유권 증명 한계(Ollama `/api/ps`는 관측자일 뿐 중재 불가) 등으로 인해 실용성과 안정성이 현저히 떨어졌다.
2. **현행 조치**: 요청 경로에서 서버 GPU 호스트, SSH 터널, 8000/8787/4318 포트 분할을 완전히 제거하고, 게이트웨이 라이브러리를 별도 서버 없이 Node 호스트 안으로 인프로세스 임포트하여, 호스트가 설정 가능한 업스트림에 직접 연결하는 구조로 정리했다(에이전트 런타임은 호스트가 띄우는 자식 프로세스로 남는다). 과거 서버 게이트웨이 사양 및 27B/FLUX 배치 계획은 역사적 설계 기록으로만 보존된다.

## 3. 핵심 차별점: 턴별 결정 모델 (`TurnPlan`) 계층

### 3.1 개념 및 필요성

기존 코딩 에이전트는 세션 시작 시 지정된 단일 모델이 전체 대화의 모든 턴을 처리하거나, 정적 휴리스틱에 따라 무거운 플래그십 모델을 일괄 투입한다. 이로 인해 단순 파일 조회나 단답형 수정에도 불필요한 고비용 모델이 호출되어 토큰과 시간을 낭비한다.

본 프로젝트의 핵심 차별화 **설계**는 **매 턴마다 경량 결정 모델이 맥락을 분석하여 실행 계획(`TurnPlan`)을 수립하는 메커니즘**이다. 이 절 전체는 설계와 검증기 구현 범위를 다루며, 하네스 런타임에는 배선되지 않았다. 현재 실제로 동작하는 모델 선택은 게이트웨이의 규칙 기반 선택(명시 모델 우선, 미지정 시 `AUTO_RULES` 경로 정책·추론 필요 여부·문맥 적합도 순)이며, 작업 유형이나 난이도로 모델을 고르지 않는다.

### 3.2 턴 플랜(`TurnPlan`) 동작 규약 및 독립 플래너 감사 결과

```
[사용자 입력 수신]
       ↓
[컨텍스트 수집]  현재 프로젝트 상태, AST 심볼 요약, 시스템 메모리(VRAM) 수집
       ↓
[TurnPlan 생성]  경량 결정 모델(카탈로그 검증 로컬 모델)이 구조화된 TurnPlan 추천
       ├─ 서브에이전트 사용 여부 및 개수 (worker, reviewer 등)
       ├─ 실행 모델 ID (로컬 7B vs 서버 32B/72B)
       ├─ 추론 등급 (reasoning grade: off | low | medium | high | xhigh)
       └─ 활성화할 스킬 (skill set)
       ↓
[결정론적 정책 검증 (Deterministic Policy Gate / Validator Prototype)]
       ├─ 모델이 카탈로그 및 allowlist에 존재하는가?
       ├─ 서버 여유 VRAM이 요청 모델을 수용 가능한가? (엔진 적재 산술은 구현, 서버 측 중재는 계획)
       └─ 예산 상한 및 프라이버시 동의 경계 준수 여부 (검증기에서 구현: V-07·V-02)
       ↓
[하네스 RPC 실행 연동]  (런타임 미연결 — 검증기는 어떤 턴 이벤트에도 구독되지 않았다)
```

- **독립 플래너 감사 결과 및 현황 (Audit Result and Current State):**
  - 독립 플래너의 가드레일 감사에서 초기 프로토타입의 경로/동의 누락, 음수 서브에이전트 상한 우회, 예산/스킬/승인 미강제, 기형 플랜 예외 처리 부재가 취약점으로 식별되었다. 이 항목들은 `decision_planner.validate_turn_plan`에서 V-02·V-06·V-07·V-09와 스키마 예외 처리로 보완되었고, 2026-11-06 시점 단위 시험이 통과한다. 남은 미구현은 V-10 핀 검사와 비용의 승인 분기다.
  - 이번 검토에서 실제 외부 전송 여부를 조사한 것은 아니며, 검증기 프로브로 확인한 범위는 "위 규칙들이 계획 레코드에서 결정론적으로 동작한다"까지다. 런타임에 연결되지 않았으므로 실제 턴에서의 집행은 확인되지 않았다.
  - 따라서 본 보고서는 `TurnPlan`과 검증기를 **"구현된 결정론적 검증기 + 런타임 미연결"**로 기술하며, "검증이 완료되어 안전한 동적 조정"이나 "완성된 런타임"으로 주장하지 않는다.
- **권고(Recommendation)와 승인(Enforcement)의 분리:** 결정 모델이 생성한 `TurnPlan`은 어디까지나 권고안일 뿐이다. 실행은 하네스의 결정론적 검증기(Policy Gate)가 승인한 값만 전달되어야 한다.
- **감사 추적 (Audit Trail, 설계):** 매 턴 수립된 `TurnPlan`과 검증 결과를 세션 원장에 남기는 규약은 설계 단계다. 현재 구현된 것은 게이트웨이의 **쿼터 원장(quota ledger)**이며, 이는 턴 원장(turn ledger)과 동일한 것이 아니다. 두 원장을 하나로 서술하지 않는다.
- **런타임 미연결 (Not Wired):** 검증기는 `TurnPlan` 레코드에 대해 동작하지만, `omp` 하네스 이벤트를 구독해 매 턴 계획을 검증하는 배선은 없다. 이는 "수정 중"이 아니라 **아직 만들지 않은 연결**이다.

## 4. 이미지 및 멀티미디어 처리 연구 (폐기/중단)

### 4.1 이미지 연구 현황 및 계획 폐기 고지

초기 연구 및 게이트웨이 스텁에서 FLUX.1 및 영상 생성 모델(Wan 2.2)의 수용이 검토되었으나, 현재 시점의 객관적 사실은 다음과 같다.

1. **이미지 및 미디어 엔진 계획은 전면 폐기/중단(abandoned)되었다.** 우리 작업에서 이미지 모델의 설치·배포·추론은 한 번도 수행되지 않았으며, 게이트웨이를 앱 라이브러리로 흡수한 현재 체제에서 서버 측 모델 배포 계획은 배제되었다.
2. **폐기된 계획 (FLUX.1-schnell 등):** 과거 `sd-server`와 FLUX.1-schnell(Apache-2.0) Q4_0을 서버에 배포하려던 구상은 적합성·적재·처리량 실측 근거가 없어 채택되지 않고 폐기되었다. 본 보고서는 어떤 이미지 성능 수치도 제시하지 않는다.
3. **GPU 임대 및 중재 폐기:** 서버 GPU 접근에 대한 실질적 임대(lease), 어드미션, 대기열 관리 계획 역시 공유 호스트 제약으로 인해 전면 폐기/중단되었다.

### 5.2 실행 기록 (Reproducible Evidence)

아래 기록은 **작성 시점과 버전에 귀속된 저자 기록**이며, 이후 코드 변경으로 유효성이 달라질 수 있는 시점 증거(time-bound evidence)다. 엔진·게이트웨이·앱 모두 시험이 계속 추가되고 있으므로 모든 주장은 시점 한정이다.

- **정책 계층 단위 테스트 (2026-11-06):** `python -m unittest discover -s engine -p "test_*.py"` 실행 기록은 전체 discovery **319건**이며, 이는 이번 선택 기능·앱 변경 전의 **과거 기준선**으로서 그 변경에 대해 재실행하지 않았다. 이 계층이 계속 편집되는 중이므로 이 수치는 실행 시점에 귀속된 기록이며, 제품 전체의 안정성을 뜻하지 않는다(과거 실행에서 실행 순서에 따라 `test_semantic_memory` 1건 오류가 관측되었고, 그 실패는 단독 실행에서 재현되지 않았다). 별도로, 검증기를 직접 프로브해 아래 계약은 실행으로 확인했다: `local_only`·동의 없음에서 클라우드 모델 `V-02` 거부, 미등록 모델 `V-03` 거부, `reasoning_grade="xhigh"`가 로컬 모델에서 `grade:clamped_xhigh_to_medium`으로 하향, `count=-3` `V-06` 거부, `cost_budget_usd=0.0`에서 유료 모델 `V-07` 거부, `context_budget_tokens` 상한 초과 `V-05` 거부, 목록 밖 스킬 `skills:dropped_unknown_*` 제거, L3 도구 `tools:widen_rejected_*`. 오케스트레이터는 동기 진입점(`run_node`·`execute_plan`·`execute_plan_parallel`)이 이미 실행 중인 이벤트 루프를 만나면 작업을 실행하지 않고 `execute_plan_async`/`run_node_async`를 안내하며 거부하며, 이 계약은 전용 모듈 `test_dag_orchestrator_loop.py`(2건)가 고정한다(직접 실행 시 `Ran 2 tests … OK`).
- **카탈로그 일관성 (현재 미통과):** `powershell -NoProfile -File scripts\verify_customization.ps1` → `VERIFICATION FAILED`, exit 1. 보고 사유는 `catalog.json is stale (differs in: valid_roles, models)`이며, 레지스트리 29개(로컬 15개) vs 커밋 카탈로그 27개(로컬 13개)의 차이다. 이 검사는 커밋된 `catalog.json`이 `engine/registry.py`에서 바이트 단위로 재생성되는지 확인한다. 즉 **생성 파이프라인은 존재하지만 현재 산출물이 레지스트리와 어긋난 상태**이며, 이 문서는 "검증 통과"로 적지 않는다. `dsh`가 패치를 수용했다는 증명은 별개로 여전히 없다.
- **로컬 하드웨어 판정:** RTX 4060 Laptop(VRAM 8.0 GiB, RAM 39.3 GiB)에서 `prototype.main` 구동 시 `standard_local`(Tier 2) 판정 기록이 있다.
- **서버 VRAM 계측(과거 조사 기록):** `cuMemGetInfo` 호출로 RTX 5090의 총 VRAM 31.36 GiB와 잔여 바이트를 수신한 과거 조사 기록이 있다. 현재 아키텍처에서는 서버 GPU 연동 계획이 폐기되었으므로 제품 런타임에 쓰이지 않는다.
- **게이트웨이 테스트의 성격:** 스텁 업스트림을 대상으로 한 **기능 테스트**(69개 통과: 기준선 62개 + 자동 선택 엔드포인트 시험 7개) 및 신규 단위 시험(도구 압축 3개, 비용 산정 2개, 2-트랙 플래너 3개, PII 마스킹 5개 등)이다. `app/test/bridge.integration.test.mjs`는 16개 하위 시험 통과 후 60초 타임아웃으로 중단되어 통합 실행은 불완전(미완) 상태다. 실제 제공자(OpenAI 호환 외부 공급자)를 붙인 실행은 시험하지 않았다. 일일 쿼터 초과 시 요청은 HTTP 429 `quota_exceeded`로 거절되며 다른 모델로 전환하지 않는다. 자격증명 리덕션은 로그·클라이언트 응답(JSON·SSE)·오류 메시지에만 적용되고, 업스트림으로 나가는 요청 본문은 가리지 않는다(`gateway/lib/upstream.mjs`). UI는 프롬프트 입력과 파일 변경 내역(diff) 보기를 제공하며 코드 에디터는 없다. 독립 리뷰 결과 지적된 결함(추론 예산의 기형·초과·미지원 값 전달, 활성 모델의 추정 식별자(`3.5`) 플레이스홀더, 영상 GET 경로의 `local_only` 우회)에 대해 코드 수정과 스텁 시험이 추가되었으나, 실제 공급자 대상 검증과 독립 보안 재검토는 완료되지 않았다. 따라서 스텁 통과를 보안 수용(security acceptance)으로 해석하지 않으며, 재검토 전까지 "안전성 검증됨"을 주장하지 않는다.
- **브라우저 회귀 시험:** `app/`의 브라우저 회귀 시험은 **51건 통과**이며, 그중 47건은 이번 자동 선택 표시 변경 전부터 존재한 시험이다. 실행 시점에 귀속된 기록이다.

### 5.3 자동 모델·추론 선택과 선택 기록 (출시된 기능)

- **자동 결정:** 사용자가 모델을 고르지 않는 기본 경로에서 게이트웨이가 경로·동의·상주 상태를 근거로 실행 모델과 추론 등급을 자동으로 정한다. 이 결정 경로는 위의 스텁 기능 시험으로 확인되었으며, 작업 유형·난이도는 판단 근거가 아니다. 실제 공급자 모델을 상대로 한 추론은 이 저장소에서 실행되지 않았으므로 추론 품질이나 비용 효과를 검증된 것으로 쓰지 않는다.
- **`GET /v1/selection`:** identity+route 단위로 마지막 결정을 돌려준다. 기록은 게이트웨이 프로세스 메모리에만 있고(용량 16) 재시작 시 초기화된다. 응답에는 프롬프트 텍스트·키·헤더가 실리지 않고, `cache-control: no-store`를 붙이며, identity가 없으면 `401`, 등록되지 않은 route는 `400`, 아직 결정이 없으면 `{"selection":null}`을 반환한다.
- **브리지 조회:** `app/server.mjs`는 이 기록을 서버 측에서 루프백으로 읽는다. 타임아웃 1.5초, 재시도 없음이며, 조회 실패는 어느 경우에도 프롬프트 라운드트립을 막지 않는다.
- **UI 표시:** 결정이 없는 세션에는 `자동`을 표시하고, 결정이 있으면 실제 모델 id와 `추론 <등급> · 생각 토큰 <budget>`을 표시한다.
- **한계(명시):** 기록의 단위는 identity+route이며 메시지 단위가 아니다. 같은 identity와 route를 공유하는 세션은 같은 모델을 표시할 수 있다. 업스트림이 스텁이므로 이 표시는 선택 결과의 반영이며 실제 추론 실행 기록이 아니다.

#### (2) 비용 계산 모델 및 업스트림 현황

- **참조 단가표(`gateway/lib/cost-rates.mjs`):** Anthropic(Claude 3.5 Sonnet: 입력 $3.0/M, 캐시 읽기 $0.3/M, 출력 $15.0/M 등), DeepSeek(V3/V4.1: 입력 $0.14/M, 캐시 읽기 $0.014/M 등), OpenAI(GPT-4o), Qwen 등의 1M 토큰당 공식 기준 요율을 하드코딩한 참조 카드를 제공하며, `calculateUsageCost`를 통해 실제 사용 비용과 노-캐시 기준선 대비 절감액을 계산한다. 단, 이 단가표는 정적 참조값이며 실시간 공급자 요금 변동과 연동되지 않는다.
- **업스트림 등록(`app/config.json`):** 기본 `demo-stub`(오프라인 데모) 외에 `openrouter-zdr`(OpenRouter 프록시, `OPENROUTER_API_KEY`), `a6api`(`A6API_KEY`)가 설정에 선언되어 있다. ZDR 플래그는 자체 설정 선언이며, 외부 공급자를 통한 실제 API 호출 추론은 일절 수행되지 않은 **미검증** 상태다.
- **파라미터 허용 목록(`gateway/lib/allowlist.mjs` 및 `chat.mjs`):** 게이트웨이 파라미터 허용 목록에 `prompt_cache_key`와 `provider`가 등록되어 있으나, `chat.mjs` 핸들러는 클라이언트가 `prompt_cache_key`를 보낼 경우 `400 unsupported_parameter`를 반환하도록 안전하게 차단한다.

### 5.5 비교 실험 (가정 기반 모의 추정 vs 실측 현황)

본 프로젝트는 최적화 파이프라인의 잠재적 효과를 정량화하기 위해 벤치마크 시뮬레이션 스크립트(`scripts/benchmark-comparison.mjs`)를 작성해 검토하였다. 그러나 **실제 LLM 모델 및 실시간 코딩 과제를 대상으로 한 엔드투엔드 비교 실험은 미측정 상태**임을 명확히 밝힌다.

#### (1) 실측 현황 고지
- **실제 모델 비교:** 표준 OMP 기준선 대비 당사 하네스의 실제 모델 추론 토큰량 및 코딩 성공률은 **전혀 측정되지 않았다.**

### 5.6 철회된 최적화 실험 (delivered 아님)

- **프롬프트 캐시(`prompt_cache_key`)와 도구 결과 길이 상한 확장(`--extension`)은 독립 검토 후 모두 철회되었다.** 제품 경로에는 어느 것도 들어가지 않았으므로 둘을 delivered 최적화로 제시하지 않는다.
- **현재 코드의 사실:** 활성 게이트웨이는 `prompt_cache_key`를 400 `unsupported_parameter`로 거절한다. 앱 설정은 `--config omp-overlay.yml`만 wiring하며, `--extension` 항목이 없음을 시험이 고정한다(현재 앱 시험 44건 중 해당 시험 포함).
- **정정된 계측:** 네이티브 산출물은 두 변형 모두에서 원본을 보존했고, 확장은 고지 문장 **350~521 바이트**를 더했을 뿐이었다. 따라서 이 둘은 토큰·비용 절감 효과의 근거가 되지 않으며, 본 보고서는 그 어떤 절감 수치도 싣지 않는다.

## 6. 경진대회 시연 계획 및 기대 효과

### 6.1 시연 시나리오 (부스 전시 라이브 시연)

경진대회는 구두 발표 없이 **부스 전시**(2026-11-18 09:00~18:00)로 진행한다. 시연은 노트북 + 24인치 모니터에서 번들 로컬 루프백 스텁(`demo-chat`)을 사용하는 **오프라인 라이브 시연**이며, 외부 네트워크·서버 연결을 전제하지 않는다. 사전 녹화 영상은 현장 장애 시의 예비 자료일 뿐이다. 시연에서는 구현된 것과 설계·미검증인 것을 화면 설명에서 구분한다.

1. **시나리오 1: 로컬 하네스 실행과 로컬 전용 대화**
   - `launch.cmd` 더블클릭 → `launch.ps1`이 `.omp-runtime\`의 Bun/omp를 확인하고 브리지를 띄우는 과정. 설치·내려받기 화면은 나오지 않는다(기본 경로는 이미 있는 것만 실행한다). 런타임이 없으면 `launch_failed`와 없는 경로가 표시되고 멈춘다.
   - 새 대화에서 클라우드 경로를 고르면 동의 카드가 먼저 뜨고, 동의 없이는 요청이 나가지 않는 장면.
   - **구분:** 하드웨어 프로파일링에 의한 Tier 판정과 티어 로컬 모델 자동 배정은 Python 계층(`engine/`)에 구현되어 있으나 **`omp` 대화 경로에 배선되어 있지 않다.** 따라서 시연에서 "하네스가 Tier 2로 자동 구성했다"고 보여 주지 않는다. 이 장면은 `prototype/`에서 분리 실행한 기록으로만 제시한다.
2. **시나리오 2: 턴별 동적 조정(`TurnPlan`) — 설계 및 검증기 시연**
   - 대화 실행 중에 `TurnPlan`이 모델·추론 등급·서브에이전트 수를 조정하는 장면은 **시연하지 않는다.** 그 배선이 없기 때문이다.
   - 대신 검증기(`validate_turn_plan`)에 계획 레코드를 넣어 경로 위반·미등록 모델·예산 초과·도구 확장 시도가 결정론적으로 거부되는 것을 화면으로 보여 준다. 이는 오프라인 계약 시연이며 런타임 집행이 아니다.
   - 과거 계획되었던 서버 GPU 오프로드(27B IQ3_S, FLUX.1-schnell, SSH 루프백 터널)는 폐기되었으므로 시연 장면에 포함되지 않는다.
3. **시나리오 3: 안전한 저하 및 정책 가드**
   - 네트워크 단절이나 잘못된 설정에서 오류 원인을 사용자에게 투명하게 표시하고 fail-closed로 기동을 중단하는 동작을 보인다. 자동 저하(degradation)·어드미션·회수는 계획 단계이거나 폐기되었으므로 구현된 기능으로 시연하지 않는다.

### 6.2 기대 효과

1. **학생 진입 비용 감소:** 기본 실행 경로는 이미 있는 런타임을 쓰고 아무것도 내려받지 않는다. 로컬 모델의 카탈로그 단가는 0이지만, 실제로 그 모델을 서빙하려면 별도 OpenAI 호환 서버가 필요하며 이 저장소가 그것을 호스팅하지는 않는다. "유휴 하드웨어를 100% 활용한다"는 식의 정량 주장은 하지 않는다.
2. **코드 자산 보안 및 프라이버시 보호:** 외부 상용 클라우드로 소스코드를 보내지 않는 것이 기본값이다. 클라우드 경로는 대화마다 새로 받은 명시 동의 없이는 헤더조차 만들어지지 않고, 로컬 슬롯은 루프백 주소만 조회한다.
3. **운용 신뢰성 확보(부분):** 모델의 무리한 실행을 막는 결정론적 정책 게이트(`TurnPlan` 검증기)와 원장 기록기는 구현되어 있고 검증기 계약은 프로브로 확인했으나, **아직 하네스 런타임에 배선되지 않았다.** 따라서 "런타임에서 환각을 자동 차단한다"고 시연하지 않는다.

## 7. 한계 및 미결 사항 (Open Issues)

1. **실제 모델 대상 정량 벤치마크 부재:** 코드 생성 성공률, 첫 토큰 응답 지연(TTFT), 토큰 절감률 등은 실제 모델을 통한 통계적 벤치마크가 수행되지 않았으며 향후 과제로 남겨둔다. `scripts/benchmark-comparison.mjs` 시뮬레이션 수치(11.2% 토큰 절감, 38.1% 비용 절감)는 임의의 출력 토큰 및 캐시 적중률 가정에 기초한 모의 추정일 뿐 실측값이 아니다.
2. **UI 완전 통합 미완:** `oh-my-pi-gui`의 참조 설계를 기반으로 프로토타입 뷰어를 구성 중이며, 독립 데스크톱 패키지로의 완전한 번들링은 추가 작업이 필요하다.
3. **폐기된 서버 27B / FLUX 계획:** 서버 27B IQ3_S 및 FLUX.1-schnell 배포 계획은 호스트 적재 실측 부재 및 서버 게이트웨이 분리안 폐기 결정에 따라 전면 폐기/중단되었다.
4. **이미지/영상 엔진 계획 폐기:** 설치·추론 실행 이력이 없고 현재의 로컬 하네스(호스트 + 에이전트 자식) 구성에 포함되지 않아 시연·평가 범위에서 완전히 배제되었다.
5. **게이트웨이 독립 보안 재검토 및 실공급자 검증 미완:** 추론 예산 전달, 모델 식별 플레이스홀더, 영상 GET 경로 우회는 코드 패치와 스텁 테스트 69개 통과가 반영되었으나, 실제 공급자 연동 시험과 독립 보안 재검토가 끝나지 않아 안전성 수용으로 보지 않는다. `app/test/bridge.integration.test.mjs` 또한 60초 타임아웃으로 미완 상태다.
6. **경계면 미봉합:** 브리지가 모델 가용성 조회에는 3값 `x-route` 헤더를 보내지만 코어의 실제 추론 호출·Python `engine/`·게이트웨이 증명/할당량 원장을 잇는 요청 단위 배선이 없다. 도구 압축 모듈 또한 번들 실행 인수(`coreArgs`)에 연결되지 않은 상태다.
7. **철회된 최적화 실험:** 프롬프트 캐시(`prompt_cache_key`)와 도구 결과 상한 확장(`--extension`)은 독립 검토 후 철회되었고 제품 경로에 없다(§5.6). 게이트웨이는 `prompt_cache_key`를 400 `unsupported_parameter`로 거절하고, 앱 설정은 `--config omp-overlay.yml`만 wiring하며 `--extension` 항목 부재를 시험이 고정한다. 정정 계측에서는 네이티브 산출물이 두 변형 모두 원본을 보존했고 확장은 고지 문장 350~521 바이트만 더했으므로, 절감 수치를 주장하지 않는다.

## 8. 결론

본 작품은 **`omp` 18.16.0 에이전트 런타임을 Node 호스트가 자식 프로세스로 띄우고, 게이트웨이는 그 호스트가 라이브러리로 인프로세스 임포트하는 로컬 하네스 기반의 학생용 무설정 AI 코딩 플랫폼**이다. (과거 연구실 RTX 5090 서버 게이트웨이 연동 및 SSH 터널링 계획은 폐기/중단되었다.)

과장된 벤치마크 수치나 조작된 결과를 배제하고, 시점이 명시된 테스트 기록(앱 154/154, 게이트웨이 148/148, 브라우저 51/51, 엔진 역사적 319)과 실제 동작하는 계측 경로, 그리고 아직 구현되지 않거나 폐기된 항목(동적 조정 런타임 미배선, 서버 GPU 연동 및 이미지 배포 폐기)을 분리해 제시한다. 이 작품이 현재 주장하는 것은 **두 실행 단위(호스트와 그 자식인 에이전트 런타임)로 이루어진 로컬 하네스의 구조와 규약, 그리고 그 규약의 어디까지가 실행으로 확인되었는가**이며, 완성된 안전성이나 엔드투엔드 통합이 아니다.
