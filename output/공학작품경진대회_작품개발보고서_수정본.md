## 1. 작품 개요

### 1.1 개발 배경: 학생 엔지니어와 연구실의 현실적 페인 포인트
최근 대규모 언어모델(LLM)을 활용한 AI 코딩 에이전트(Codex, Claude Code, Cursor 등)가 개발의 표준 도구로 자리잡고 있습니다. 그러나 컴퓨터공학·SW 전공 학부생과 대학원생, 동료 학생 심사위원들이 마주하는 실제 현실은 다음과 같은 심각한 장벽에 부딪혀 있습니다.

1. **학생에게 너무나 가혹한 상용 구독료 부담 (월 20달러 = 학식 4~5끼 가격):**
   - Cursor, GitHub Copilot 등 상용 도구의 월 20달러(약 3만 원) 구독료는 수입이 없는 대학생에게 매달 학식 4~5끼를 포기해야 하는 직접적인 경제적 부담입니다.
   - 상용 API를 직접 연동하더라도, 코드를 몇 번만 탐색하고 수정하면 순식간에 수천 원~수만 원의 API 요금이 청구되므로 학생들은 마음 놓고 질문하거나 실험적인 디버깅을 시도하지 못하고 위축됩니다.
2. **과제, 캡스톤 디자인, 랩실 연구에서의 토큰 비용 공포:**
   - 대규모 캡스톤 프로젝트나 랩실 연구용 소스코드는 수만 줄에 달합니다. 파일 몇 개만 LLM에 넘겨도 컨텍스트 윈도우가 꽉 차고 토큰 비용이 폭증하여, "질문 한 번에 1달러씩 날아가는 것 아닌가" 하는 불안감에 밤샘 디버깅 도중 AI 활용을 중단하는 사례가 빈번합니다.
3. **방치되는 연구실 고성능 GPU와 개인 노트북 하드웨어 자원:**
   - 많은 공학 랩실에 NVIDIA GeForce RTX 4090(24GB VRAM) 등 훌륭한 GPU 서버가 구비되어 있고, 학생들의 개인 노트북에도 2~8GB VRAM의 외장/내장 GPU가 탑재되어 있습니다. 그러나 기존 도구들은 단순 원격 API 프록시로만 동작하여 로컬 하드웨어를 100% 놀려두거나, 반대로 일반 노트북에서는 실행조차 불가능한 양극화 문제를 낳습니다.
4. **부수 작업(세션 압축, 커밋 메시지, 메모리 정제)에 따른 메인 UI 지연과 토큰 낭비:**
   - 대화가 길어질 때 컨텍스트를 요약하거나 Git 커밋 메시지, 세션 제목을 생성하는 보조 작업에 메인 LLM을 호출하느라 대화 흐름이 뚝뚝 끊기고 귀중한 토큰이 허공으로 사라집니다.
5. **설정 지옥(Configuration Hell):**
   - 오픈소스 온디바이스 도구들은 파이썬 환경 설정, CUDA 버전 호환, 양자화 파라미터 계산, 모델 다운로드 및 프롬프트 튜닝 등 수많은 진입 장벽을 요구하여 코딩에 집중해야 할 학생들을 지치게 만듭니다.

### 1.2 개발 목적 및 사용자 대상 (Zero-Config 자동화 철학)
본 작품의 최종 목적은 **"복잡한 설정 없이 다운로드 한 번으로 실행하면 내 PC/노트북 사양에 맞춰 0원짜리 로컬 LLM부터 초저가 모델까지 자동 최적화되고, 연구실 RTX 4090 서버나 개인 노트북으로 100% 무료·무제한 AI 코딩 환경을 제공하는 단일 배포형 지능형 애플리케이션"**을 구현하는 것입니다.

- **학생 심사위원단 맞춤형 핵심 UX 철학:**
  - **설정 제로 (Zero-Config):** Python 설치, CUDA 설정, 토큰 예산 배분, 양자화 옵션을 학생이 고민할 필요가 없습니다. 다운받아 더블클릭하면 `HardwareProfiler`가 0.2초 만에 CPU/RAM/VRAM을 측정해 최적의 4-Tier 로컬 실행 경로를 자동 확정합니다. 기본 모드는 `mode="auto"` 단 하나입니다.
  - **0원 무제한 디버깅 (Unlimited Free Coding):** 학부 과제, 캡스톤 디자인, 연구실 코드베이스에서 API 비용 걱정 없이 수백 번, 수천 번 질문하고 디버깅할 수 있습니다. 로컬 티어(Tier 1~3) 처리 구간의 API 비용은 **정확히 USD 0 (0원)**입니다.
  - **하드웨어 적응형 4-Tier 로컬 실행 아키텍처:**
    - **Tier 0 (순수 규칙 · 클라우드 위임):** RAM < 8GB 내장그래픽 노트북. 로컬 LLM 0개, AST 파서·FTS5·정규식으로 VRAM 0MB 구동하며, 필요 시 초저가 모델(`deepseek-v4.1-flash`, 1M 토큰당 입력 $0.06 / 출력 $0.12)로 학식 반 끼도 안 되는 비용으로 수십 개 과제 완결.
    - **Tier 1 (1.5B·3B GGUF):** RAM 8~16GB / VRAM 2~4GB 보급형 노트북. AST 심볼 트리아지 및 마이크로 함수 생성을 온디바이스 USD 0 완결.
    - **Tier 2 (7B·8B GGUF):** RAM ≥ 16GB / VRAM ≥ 6GB 중고급 개발 노트북. Track 1 단일 구현 및 1차 코드베이스 탐색을 100% 온디바이스 로컬 처리.
    - **Tier 3 (27B·32B 플래그십 로컬 가속 노드):** 랩실 RTX 4090(24GB VRAM) 환경. 혁신적인 3진수(Ternary 2.13 bpw) 모델 `Prism ML Bonsai 2 27B`를 탑재하여 복합 구현과 262K 컨텍스트 코드 분석을 100% 로컬 무료 완결.
  - **Bonsai 2 27B 백그라운드 인지 전담 (Zero Lag & Zero Cost):**
    - 6.7 GiB VRAM의 극단적 경량성과 초당 85 토큰의 압도적 속도를 가진 `Prism ML Bonsai 2 27B`가 메인 대화 흐름을 방해하지 않고 **세션 압축, 커밋/세션 제목 자동 생성, FTS5 지식 증류, 루프 가드 및 진단**을 백그라운드에서 0원/0ms 지연으로 도맡아 처리합니다.
  - **프롬프트 기반 2-Track 자율 실행:**
    1. **Track 1 (간단/명확한 작업):** 함수 작성, 오타/린트 수정, 단순 버그 수정은 기획 비용 없이 **로컬 온디바이스(Tier 1~3) 또는 Flash 직행**으로 즉각 구현·테스트.
    2. **Track 2 (복잡/불명확한 작업):** 아키텍처 재설계, 다중 파일 리팩터링 등은 **JevBench 기반 개발자 고정 결정 모델 프리셋 5종(`baseten/mammoth-1` 주 결정 외 4종) 기반 1단계 조사(`researcher`) → 구조화된 계획(`planner`) → 격리 구현·단위 테스트 검증**으로 오류 없는 실행 보장.
- **핵심 사용자:** 과제와 캡스톤으로 밤을 새우는 공학 대학생, 랩실 연구원, 1인 개발자, 바이브 코더 (단 하나의 자연어 입력창 제공).
- **공학적 신뢰성:** 262K 초대형 컨텍스트 지원, 삼진 양자화 85 tok/s 초고속 스트리밍, 22개 엄격한 엔지니어링 단위/통합 테스트 스위트 100% 통과로 동료 학생 심사위원단의 기술적 탄성을 자아내는 구조적 완성도를 확보했습니다.

## 2. 시스템 아키텍처 설계

### 2.1 전체 시스템 구조 (단일 배포형 통합 애플리케이션)
본 플랫폼은 **단일 배포형 통합 애플리케이션(Single Distributable Application)**으로 설계됩니다. **OpenCodex 기반 모델 게이트웨이**는 별도 서버로 분리되지 않고 **DeepSeek Harness 런타임 내부의 임베디드 컴포넌트(embedded gateway)**로 직접 탑재됩니다. 사용자는 하나의 설치 패키지(단일 바이너리 또는 데스크톱 설치 파일)를 실행하는 것만으로 게이트웨이, 오케스트레이터, GUI, 로컬 저장소, 백그라운드 인지 엔진을 동시에 얻습니다.

```
+==========================================================================+
| [단일 배포 패키지] DeepSeek Harness 통합 애플리케이션                    |
| 1회 설치 · 상시 서버 불필요 · 인바운드 포트 없음 · 학생 친화적 Zero-Config|
+==========================================================================+
| (1) Desktop GUI         단일 입력창 · mode="auto" · 진행/비용(0원) 표시   |
| (2) 2-Track Pipeline    Track 1 즉시 구현 / Track 2 조사→계획→구현       |
| (3) Local Orchestrator  Plan·Budget 제어 · worktree/스냅샷 격리·복구     |
+--------------------------------------------------------------------------+
| (4) HardwareProfiler    CPU/RAM/VRAM 자동 탐지 → 4-Tier 실행 확정        |
| (5) Tiered Executor     Tier 0 규칙/클라우드 → Tier 1 1.5B/3B GGUF       |
|      · Tier 2 7B/8B GGUF → Tier 3 27B/32B (Bonsai 2 / GGUF) · 로컬 USD 0 |
|      · 결정 프리셋 5종(JevBench): mammoth-1 · drex-max · subq-snap       |
|      · d1-ultra · elephant-9b / 코드 Flash / 승격 Sonnet 4.5             |
+--------------------------------------------------------------------------+
| (6) 백그라운드 인지 엔진  Prism ML Bonsai 2 27B (6.7GB VRAM, 85 tok/s)    |
|      · 세션 압축 (262K 컨텍스트 요약) · 커밋/세션 제목 자동 생성         |
|      · FTS5 지식 증류/정제 · 루프 가드 & 트리아지 진단 (UI 지연 0ms, 0원)|
+--------------------------------------------------------------------------+
| (7) 임베디드 OpenCodex 게이트웨이  (in-process, 포트 노출 없음)          |
|      · Provider 커넥터(OpenRouter / Baseten) / 스트리밍 / Key 마스킹     |
|      · 프라이버시 경로 강제(No-Log 기본) / 프리셋 카탈로그 로더          |
+--------------------------------------------------------------------------+
| (8) Context & Memory    SQLite+FTS5 · AST 슬라이싱 · 무손실 압축 · 캐시  |
+==========================================================================+
        │  아웃바운드 HTTPS 만 사용 (인바운드 리스닝 없음)
        ├───────────────────────────┬───────────────────────────┐
        ▼                           ▼                           ▼
  Baseten (mammoth-1)      OpenRouter (Zero Retention)   A6API / 외부 프록시
```

1. **임베디드 OpenCodex 게이트웨이:**
   - Harness 프로세스 내부에서 in-process로 동작하는 경량 API 프록시입니다. 별도 서버 프로세스, 컨테이너, TLS 인증서, 리버스 프록시 구성이 필요 없습니다.
   - Provider 연결, API 키 마스킹, 실시간 스트리밍 중계, 토큰·비용 집계, 프라이버시 경로 강제를 담당합니다.
   - 외부로부터의 인바운드 연결을 수신하지 않고 아웃바운드 HTTPS 요청만 수행하므로, 로컬 방화벽 포트 개방이나 서버 측 공격면이 존재하지 않습니다.
   - **프리셋 카탈로그 로더:** 앱 패키지에 포함된 검증 완료 모델/하네스 프리셋을 읽어 실행 구성으로 변환합니다. 카탈로그는 런타임 스크래핑이 아니라 **서명된 앱 업데이트**로만 갱신됩니다.
2. **DeepSeek Harness 실행 코어 및 로컬 적응형 실행 계층:**
   - 사용자 PC에서 직접 코드를 수정하고 터미널 명령 및 테스트를 수행하는 실행 주체입니다. 파일 시스템과 셸 권한은 로컬 프로세스에만 존재하며 외부로 이전되지 않습니다.
   - **HardwareProfiler & Tiered Execution:** 앱 기동 시 CPU 코어, 사용 가능 RAM, GPU 가속 지원(VRAM)을 정밀 진단하여 4개 티어(Tier 0 규칙 기반 ~ Tier 3 온디바이스 LLM) 중 최적 구성을 자동 확정합니다.
   - 로컬 처리 가능 작업은 온디바이스에서 완결하여 API 비용을 USD 0으로 억제하며, 고난도·원격 협업이 필요한 작업만 임베디드 게이트웨이를 통해 클라우드 모델로 안전하게 라우팅합니다.
   - 2-Track 파이프라인, 계획 검증기, 예산 제어기, 격리 작업공간(Git worktree / SQLite 파일 스냅샷), 상태 체크포인트 및 장애 복구 엔진을 탑재합니다.
3. **Prism ML Bonsai 2 27B 백그라운드 인지 전담 엔진 (인지 오프로딩 계층):**
   - 메인 사용자의 상호작용 및 코드 생성 흐름과 완전히 분리된 비동기 워커 스레드로 동작합니다.
   - 3진수 가중치 압축(PQ2_0, 2.13 bpw) 덕분에 6.7 GiB VRAM만 점유하면서 초당 85 토큰으로 인지 잡을 처리합니다.
   - **세션 압축**, **세션/커밋 제목 자동 생성**, **FTS5 메모리 정제 및 지식 증류**, **루프 가드 및 진단** 등 연산 집약적 보조 인지 작업을 메인 UI 블로킹 없이 0ms 지연 및 API 비용 USD 0으로 백그라운드 완결합니다.
4. **프리셋 카탈로그(배포 자산):**
   - 클라우드 주력 코드 생성 모델(`deepseek/deepseek-v4.1-flash-1017`), JevBench 기반 개발자 고정 결정 모델 프리셋 5종(`baseten/mammoth-1`, `openrouter/drex-max`, `openrouter/subq-snap-1.1`, `openrouter/d1-ultra`, `openrouter/elephant-9b`), 플래그십 승격 모델(`anthropic/claude-sonnet-4.5`), 로컬 4-Tier별 권장 양자화 모델 사양(GGUF Q4_K_M), 하네스 템플릿, 정책 메타데이터를 담은 버전 고정 JSON 자산입니다. 앱 바이너리와 함께 배포되며, 카탈로그 버전이 실행 로그와 비용 원장에 기록되어 결과 재현의 기준이 됩니다.

**단일 배포형 구조의 이점 (동료 학생 엔지니어 및 랩실 관점):**

- **운영 부담 및 서버비 제로:** 상시 가동 서버, 모니터링, 도커 설정이 일체 불필요합니다. 학생이나 연구실 팀원이 바이너리 하나만 공유받아 실행하면 즉시 완전한 개발 환경이 구축됩니다.
- **설치 즉시 동작 (Zero-Config):** 심사위원이 패키지를 실행하면 그 자리에서 전체 기능이 그대로 재현됩니다. 연구실 방화벽이나 캠퍼스 네트워크 환경에 구애받지 않습니다.
- **아키텍처 복잡도 최소화:** 별도의 서버 관리 지점이 없어 1인 개발자나 소규모 학부 캡스톤 팀이 유지보수하기에 최적입니다.
- **지갑 걱정 없는 무제한 코딩:** 로컬 하드웨어(노트북 또는 연구실 서버)를 100% 활용해 비용 청구서 없는 안심 코딩이 가능합니다.

### 2.2 자동화 실행 및 의사결정 파이프라인 (2-Track + Background Cognitive Engine)
```
[사용자 요청 (과제/캡스톤/연구 코딩)]
   ↓
[HardwareProfiler: CPU/RAM/VRAM 자동 진단 → 4-Tier 확정 (Tier 0 규칙/클라우드 → Tier 1 1.5B/3B → Tier 2 7B/8B → Tier 3 27B/32B Bonsai/GGUF)]
   ↓
[로컬 보안 검사 및 파일 격리 환경 초기화]
   ↓
[트랙 판정: 규칙·휴리스틱 + JevBench 고정 결정 프리셋 1회 (1차 필터 elephant-9b → 주 결정 mammoth-1)]
   ├─ Track 1 (간단/명확) ──→ [즉시 구현: 로컬 티어(Tier 1~3) 또는 Flash 직행] ──┐
   └─ Track 2 (복잡/불명확) ─→ [1단계 조사: researcher (로컬/경량)]              │
                              → [2단계 계획: planner (JevBench 결정 프리셋 5종)] ┤
                                                                                 ▼
[임베디드 게이트웨이: 로컬 GGUF 또는 클라우드 프리셋 모델 라우팅 + 프라이버시 경로 검증]
   ↓
[격리 작업공간 구현: Git worktree / SQLite 스냅샷]
   ↓
[검증 엔진: 테스트 · 린트 실행]
   ├─ 실패 → [국소 재계획 / 상위 로컬 티어 또는 클라우드 승격(Flash -> Sonnet 4.5)]
   └─ 성공 → [결과 리포트 · 비용(로컬 USD 0)/토큰 집계 완료]
   
   ─────────────────────── [비동기 백그라운드 인지 파이프라인] ───────────────────────
   │ 메인 대화/UI 지연시간 0ms 유지 (전담: Prism ML Bonsai 2 27B / Ternary 6.7GB VRAM)
   ├─ [세션 압축]: 대화 토큰 누적 시 262K 대형 윈도우 기반 과거 히스토리 무손실 계층 압축
   ├─ [커밋/제목 생성]: 변경된 Git diff 분석을 통한 시맨틱 세션 제목 및 표준 커밋 메시지 합성
   ├─ [FTS5 지식 증류]: 반복 해결 패턴·코드 스니펫을 SQLite FTS5에 자동 정제 및 인덱싱
   └─ [루프 가드 & 트리아지]: 서브에이전트 반복 에러 및 무한 루프 징후 백그라운드 감지·개입
```

- **Track 1**은 계획 단계의 추가 추론 비용을 지불하지 않습니다. 판정 자체도 규칙·휴리스틱과 단일 경량 호출로 처리하여 계획 오버헤드가 0에 가깝습니다. Tier 1~3 환경에서는 로컬 온디바이스에서 즉시 코드를 생성하여 API 비용 USD 0 및 초저지연으로 구현합니다.
- **Track 2**는 조사(`researcher`) → 계획(`planner`, JevBench 고정 결정 프리셋 5종 활용: 1차 필터 `elephant-9b` → 주 결정 `mammoth-1` 등) → 격리 구현 → 리뷰의 고정 순서를 따릅니다. 단계 수와 역할이 프리셋에 명시되어 있어 실행 경로가 예측 가능합니다.
- **백그라운드 인지 엔진**은 메인 UI 스레드와 완전히 분리된 큐(Queue) 방식으로 구동됩니다. 사용자가 다음 프롬프트를 작성하거나 결과를 확인하는 동안 `Prism ML Bonsai 2 27B`가 백그라운드에서 세션 압축, 커밋 메시지 생성, 지식 증류를 묵묵히 수행하므로 사용자가 체감하는 대기 시간은 **0ms**이며 추가 비용은 **0원**입니다.
- 모델 선택을 런타임에 방황하지 않고, 오프라인 검증된 프리셋과 로컬 엔진이 고정 분담하여 결정론적 안정성을 제공합니다.

## 3. 핵심 기술 및 단계별 개발 내용

### 3.1 1단계 — 단일 배포형 통합 런타임 구축 (Harness + Embedded Gateway)
- **단일 패키지 빌드 파이프라인:** GUI, Harness 실행 코어, 임베디드 OpenCodex 게이트웨이, SQLite 저장소, 프리셋 카탈로그를 하나의 배포 아티팩트로 묶습니다. 빌드 산출물은 Windows 단일 실행 파일을 기준으로 하며, macOS/Linux 패키징은 동일 소스에서 파생됩니다.
- **게이트웨이 내장화:** OpenCodex 게이트웨이를 별도 FastAPI/Rust 서버 프로세스가 아닌 in-process 모듈로 링크합니다. Provider 커넥터, 스트리밍 중계, 키 마스킹, 비용 집계, 프라이버시 경로 강제를 라이브러리 인터페이스로 노출하여 Harness가 직접 호출합니다.
- **무서버 네트워크 모델:** 인바운드 리스닝 포트를 열지 않고 아웃바운드 HTTPS만 사용합니다. 따라서 TLS 인증서 발급, 리버스 프록시, 방화벽 개방, 서버 패치가 모두 불필요합니다.
- **로컬 상태 완결성:** 세션, 캐시, 비용 원장, 프리셋 버전을 모두 로컬 SQLite에 저장합니다. 서버 측 사용자 계정이나 원격 상태 저장소가 없으므로 오프라인에서도 이전 세션을 이어서 사용할 수 있습니다.
- **업데이트 채널:** 앱 업데이트는 ① 바이너리 교체, ② 서명된 프리셋 카탈로그 갱신의 두 부분으로 구성됩니다. 프리셋만 갱신하는 경량 업데이트와 전체 바이너리 업데이트를 분리하여 배포 주기를 유연하게 운영합니다.

### 3.2 2단계 — 하이브리드 메모리 및 백그라운드 인지 최적화 (Prism ML Bonsai 2 27B 연계)
- **경량 시스템 프롬프트 및 지침 정제:** 프롬프트 중복을 제거하고 작업 맥락에 필요한 최소 지시사항만 동적 주입합니다.
- **AST 기반 심볼 슬라이싱(AST Symbol Slicing) 및 캐싱:** 파서 기반 구문 트리 분석으로 필요한 함수·클래스 영역만 정밀 추출하여 대용량 파일 전체 읽기를 차단하고, 컨텍스트 토큰을 **70~85% 절감**합니다.
- **SQLite + FTS5 기반 새니타이즈 전문 검색:** 쿼리 특수문자와 인젝션을 사전 정제한 뒤 BM25 랭킹 검색을 수행합니다. 임베딩 모델과 GPU를 전혀 사용하지 않으므로 **VRAM 0**으로 동작하며, 핵심 결정·규칙을 **5ms 이내**에 검색합니다.
- **Prism ML Bonsai 2 27B 백그라운드 인지 전담 파이프라인 (Full Background Cognitive Offloading):**
  - 메인 사용자의 코딩 상호작용 및 UI 반응성을 방해하지 않도록, 연산 집약적인 백그라운드 인지 잡 전반을 6.7 GiB VRAM 점유 / 초당 85 토큰 속도의 `Prism ML Bonsai 2 27B`가 **비용 0원(USD 0) 및 영지연(UI 블로킹 0ms)**으로 백그라운드 스레드에서 전담 수행합니다.
  - **1) 세션 압축 (Session Compaction):** 대화와 턴 수가 누적되어 컨텍스트 임계치(예: 32K~64K 토큰)에 도달할 때, Bonsai 2의 262K 대형 윈도우를 활용하여 과거 히스토리, 도구 실행 결과, 중간 디버깅 궤적을 핵심 상태(목표, 완료된 수정, 미결 과제)로 압축 요약함으로써 메인 턴의 토큰을 대폭 절약합니다.
  - **2) 세션 및 커밋 제목 자동 생성 (Title & Commit Generation):** 변경된 Git diff와 작업 내역을 비동기 분석하여 가독성 높은 세션 제목과 Conventional Commits 규격의 Git 커밋 메시지를 백그라운드에서 지연 없이 자동 합성합니다.
  - **3) FTS5 메모리 정제 및 지식 증류 (Memory Distillation):** 세션 중 발견된 저장소 고유의 빌드 규칙, 에러 해결 스니펫, 환경 변수 특이사항을 백그라운드에서 증류(Distillation)하여 SQLite FTS5 전문 검색 테이블에 주기적으로 정제·인덱싱합니다.
  - **4) 루프 가드 및 진단 (Loop Guard & Triage):** 서브에이전트 워커가 동일 에러를 반복하거나 무한 루프에 빠질 조짐을 보일 때, Bonsai 2가 워커의 실패 로그를 백그라운드에서 진단하여 오케스트레이터에 즉시 우회 전략을 제안합니다.
- **TokenEconomizer 3종:**
  - **마이크로 스킬(Micro-Skills) 누적 캐싱:** 동일 저장소에서 반복되는 빌드·테스트 명령(예: `python -m pytest`, 특정 환경변수)을 세션 간 지속 저장하여 초기 탐색 비용을 제거합니다.
  - **도구 동적 가지치기(Tool Pruning):** 다중 턴 동안 사용되지 않는 도구 정의 메타데이터를 시스템 프롬프트에서 제외하여 매 턴 수백 토큰의 낭비를 차단합니다.
  - **실패 루프 능동 개입:** Bonsai 2 백그라운드 진단과 연계하여 동일 에러 2회 이상 발생 시 즉각적인 방향 전환(Redirect)을 명령합니다.
- **격리 및 롤백:** 구현 단계는 **Git worktree** 또는 **SQLite 파일 스냅샷**으로 격리합니다. 실패 시 해당 작업공간만 폐기하므로 사용자의 기존 작업 트리를 오염시키지 않고 즉시 원상 복구됩니다.

  - **일관된 사용자 경험:** 사용자는 버전이 다른 앱에서 서로 다른 라우팅 결과를 겪지 않으며, 업데이트 노트로 개선 사항을 명시적으로 확인할 수 있습니다.
- **프라이버시 정책 강제(게이트웨이 내장):**
  - **학습 비동의(기본값):** OpenRouter의 Zero Data Retention / No-Log 경로만 허용합니다.
  - **학습 동의 시:** 검증된 A6API 등 초저비용 프록시 경로까지 후보를 확장합니다. 정책 위반 요청은 임베디드 게이트웨이가 전송 전에 차단합니다.

### 3.4 4단계 — 하드웨어 적응형 4-Tier 로컬 실행 아키텍처 및 4090 로컬 가속 엔진 (Hardware-Adaptive Tiered Local Execution Architecture)
본 플랫폼은 사용자의 PC 하드웨어 사양에 구애받지 않고 일관된 개발 경험을 제공하기 위해, **순수 규칙 기반/클라우드(Tier 0)부터 온디바이스 GGUF 및 초경량 3진수 가속 추론(Tier 1~3)까지 하드웨어에 따라 확정되는 4단계 로컬 실행 티어(4-Tier: Tier 0 순수 규칙/클라우드 → Tier 1 1.5B/3B GGUF → Tier 2 7B/8B GGUF → Tier 3 27B/32B 플래그십 로컬 가속 노드)**를 구축합니다.

Tier 1~2 로컬 언어모델은 메모리 효율성과 양자화 손실을 최소화한 **GGUF Q4_K_M 포맷**을 표준으로 사용하며, Tier 3 고성능 로컬 가속 노드(RTX 4090 24GB 환경)에서는 최신 **3진수 가속 패킹(Ternary 1.72~2.13 bpw, PQ2_0) 모델 `Prism ML Bonsai 2 27B`** 및 32B GGUF를 표준 엔진으로 배치합니다.

#### (1-가) 플래그십 로컬 가속 노드 상세: Prism ML Bonsai 2 27B 및 상호 보완 아키텍처

1. **아키텍처 및 3진수(Ternary) 가중치 압축:**
   - Qwen3.8-27B 인과적 백본(Causal Backbone)을 기반으로 Hadamard 블록 단위 회전(Blockwise Rotation) 기법을 적용, 1.72~2.13 bpw(PQ2_0 패킹) 3진수 가중치 {-1, 0, +1}로 최적화되었습니다.
   - 모델 가중치 전체가 단 **6.7 GiB VRAM**만 점유하므로, 24GB VRAM을 갖춘 RTX 4090 기준 **16 GiB 이상의 순수 VRAM을 고속 KV 캐시로 온전히 할당**할 수 있습니다.
2. **262K (262,144 토큰) 대규모 컨텍스트 네이티브 수용:**
   - 방대한 여유 VRAM 덕분에 CPU RAM 오프로딩이나 컨텍스트 스와핑 없이 **262K 토큰에 달하는 전체 코드베이스를 단일 턴에 직접 VRAM에 적재**하여 정밀 분석합니다.
3. **RTX 4090 하드웨어 실측 가속 성능:**
   - **생성 처리량 (Generation Throughput):** 초당 **85 tokens/sec**의 고속 스트리밍 생성을 달성합니다.
   - **프롬프트 프리필 속도 (Prompt Prefill Speed):** 초당 **3,280 tokens/sec**로, 1,000 토큰 규모의 코드 프롬프트에 대한 첫 번째 토큰 반환 지연(TTFT, Time-To-First-Token)이 **0.3초 미만(< 0.3s)**에 불과합니다.
4. **벤치마크 품질 검증 (압축 손실 최소화):**
   - 14개 주요 코딩 및 추론 벤치마크 평균 점수 **84.78**을 기록하여, 비압축 FP16 기준선 성능의 **98.2%**를 완벽히 보존합니다.
   - **LiveCodeBench 90.07**, **HumanEval+ 95.12**, **MATH-500 98.80**, **AIME26 95.83**을 달성하여 상용 클라우드 플래그십에 필적하는 코딩 및 알고리즘 구현력을 로컬에서 발휘합니다.
5. **Baseten Mammoth-1 (27B)과의 상호 보완 공존 및 백그라운드 인지 전담 분업:**
   - 4090 로컬 가속 노드 환경에서 `Mammoth-1 (27B)`은 영지연·초저비용의 신뢰성 높은 의사결정/트리아지 분류기(Decision/Triage Classifier)로 작동합니다.
   - `Bonsai 2 (27B)`는 262K 장기 컨텍스트 심층 추론(Thinking)과 로컬 코드 생성을 담당할 뿐만 아니라, **세션 압축, 커밋/세션 제목 자동 생성, FTS5 지식 증류, 루프 가드 트리아지**의 4대 백그라운드 인지 작업을 완전 비동기로 전담합니다.
   - 6.7 GiB의 극단적인 경량성 덕분에 두 27B 모델은 RTX 4090 24GB VRAM 내에서 여유롭게 공존(합산 13.4 GiB 점유, 10 GiB 이상의 KV 캐시 상시 확보)하며, 메인 사용자 코딩 대화와 백그라운드 인지 연산이 서로를 전혀 간섭하지 않고 병렬 구동됩니다. 이를 통해 메인 대기 시간 0ms, 백그라운드 인지 비용 0원을 달성합니다.

#### (2) 하드웨어 자동 프로파일링 및 Zero-Config UX (HardwareProfiler)
- **무설정(Zero-Config) 자동 탐지:** 사용자가 모델 양자화 비트, GPU 레이어 오프로딩 수(`n_gpu_layers`), 스레드 수, 컨텍스트 크기를 수동 계산할 필요가 없습니다. 앱 초기 구동 시 `HardwareProfiler`가 백그라운드에서 시스템 자원을 0.2초 이내에 자동 측정합니다.
  - CPU: 물리 코어 수, 논리 스레드 수, 지원 SIMD 명령어 세트 (AVX2, AVX-512, ARM NEON).
  - RAM: 전체 물리 메모리 크기 및 현재 가용 여유 메모리.
  - GPU: DirectML/CUDA 가용 디바이스, 드라이버 버전, 전용 VRAM(VRAM Dedicated Memory).
  - 스토리지: 로컬 캐시 및 모델 가중치 저장을 위한 여유 디스크 공간.
- **결정론적 티어 확정:** 측정된 프로파일을 기반으로 `Tier 0~3` 중 안정성이 100% 보장되는 최적 티어를 자동 확정하여 로컬 런타임에 바인딩합니다.
- **투명한 UI 표시:** 확정된 실행 티어와 로컬 메모리 점유 상태는 Desktop GUI 우측 상단 상태바에 간결하게 표시되며(예: `[Tier 2: Qwen2.5-Coder-7B-Q4 | VRAM 4.2GB/8.0GB]`), 사용자 조작을 강제하지 않는 순수 가시성 정보로 제공됩니다.

#### (3) 엣지-클라우드 하이브리드 라우팅 및 다층 폴백 메커니즘 (Hybrid Edge-Cloud Routing)
로컬 하드웨어 자원의 효율성과 클라우드 거대 모델의 최상위 지능을 유기적으로 융합합니다.
- **역할 분담 (Local-First Hybrid Architecture):**
  - **로컬 티어 (Edge):** 기밀성이 요구되는 내부 소스코드 탐색, 단순 기능 구현, AST 심볼 슬라이싱, 단위 테스트 스캐폴딩 등 일상적·반복적 코딩 작업을 **지연시간 0 및 비용 USD 0**으로 즉시 처리합니다.
  - **클라우드 티어 (Cloud):** 다중 모듈 아키텍처 재설계, 2-Track 복합 DAG 계획 수립(JevBench 고정 결정 프리셋 5종: `baseten/mammoth-1`, `openrouter/drex-max`, `openrouter/subq-snap-1.1`, `openrouter/d1-ultra`, `openrouter/elephant-9b`), 고난도 보안 취약점 감사(`anthropic/claude-sonnet-4.5`)와 같은 최고 지능이 요구되는 핵심 의사결정 구간에만 선별 호출합니다.
- **다층 장애 복구 및 우아한 강등(Graceful Degradation):**
  - **1단계 (컨텍스트 축소):** 로컬 온디바이스 모델 추론 중 Out-of-Memory(OOM) 징후 발생 시, AST 파서가 컨텍스트 윈도우를 핵심 심볼 위주로 즉각 축소합니다.
  - **2단계 (티어 강등):** 지속적인 메모리 부족 또는 허용 토큰 생성 속도(예: < 5 tokens/s) 미달 시, 하위 티어(예: Tier 2 -> Tier 1 또는 Tier 0)로 런타임 강등합니다.
  - **3단계 (클라우드 승격):** 로컬 모델의 단위 테스트 검증이 2회 연속 실패하거나 모델 지능 한계에 도달한 경우, 내장 게이트웨이가 즉시 주력 코드 생성 모델(`deepseek/deepseek-v4.1-flash-1017`) 또는 플래그십 승격 모델(`anthropic/claude-sonnet-4.5`)로 에스컬레이션하여 작업의 최종 완결성을 100% 보장합니다.

#### (4) 경제성, 프라이버시 및 개발 접근성 혁신 효과
- **비용 최적화 (Extreme Cost Reduction):** 전체 요청 중 60~85%를 차지하는 단순/반복 구현 노드를 로컬 티어(Tier 1~3)에서 USD 0으로 흡수함으로써, 순수 클라우드 의존 시스템 대비 개발 API 발생 비용을 **최대 80% 추가 절감**합니다. JevBench 기준 결정 단가 USD 0.012~0.031 per 1k decisions의 결정 프리셋을 사용하므로, 고가 플래그십 모델로 계획을 수립하던 기존 구성 대비 의사결정 비용도 함께 절감됩니다.
- **프라이버시 완벽 보호 (Data Sovereignty):** 사내 보안 코드나 민감한 비즈니스 로직을 외부 클라우드에 단 1토큰도 전송하지 않고 로컬 환경에서 폐쇄적으로 처리할 수 있어, 엄격한 보안 규정을 준수합니다.
- **범용적 접근성 (Universal Accessibility):** 4GB 메모리의 저사양 보급형 PC(Tier 0)부터 수십 GB VRAM의 전문가용 워크스테이션(Tier 3)까지 모든 하드웨어 환경에서 단 하나의 설정 조작 없이 최적의 성능을 발휘합니다.

## 4. 사용자 인터페이스 및 경진대회 시연 범위

### 4.1 사용자 인터페이스 및 기본 실행 모드
- **기본 모드 `mode="auto"` (Zero-Config):** 사용자는 자연어 입력창 하나만 사용합니다. 하드웨어 사양 기반 로컬 실행 티어(Tier 0~3), 모델 선택, 추론 강도, 예산, 프라이버시 경로, 에이전트 구성은 모두 시스템과 프리셋이 자동 결정합니다.
- **자동 노출 정보 (대시보드):** 현재 하드웨어 실행 티어(`Tier 0`~`Tier 3`) 및 로컬 점유 메모리, 실행 중인 트랙(Track 1/Track 2), 사용 모델(로컬 GGUF / 주력 코드 생성 / 결정 5종 / 승격), 누적 토큰·비용(로컬 처리 구간 USD 0 표기), 프라이버시 경로, 격리 작업공간 상태를 읽기 전용으로 표시합니다. 이는 사용자 설정이 아니라 투명성 제공입니다.
- **고급 모드(선택):** 프리셋이 제공하는 범위 내에서만 조정할 수 있습니다.
  1. **품질 우선:** 프리셋의 승격 티어를 조기에 사용하고 리뷰 단계를 항상 포함합니다.
  2. **균형 (auto의 기본 프로파일):** Track 판정에 따라 로컬 티어, 주력 모델 및 폴백 티어를 자동 선택합니다. 별도 조작이 없으면 이 프로파일이 적용됩니다.
  3. **비용 우선:** 로컬 티어 완결률을 극대화하고 클라우드 승격을 최후 수단으로 제한하며 캐시 재사용을 극대화합니다.
  4. **속도 우선:** 로컬 SLM(Tier 1~2) 및 저지연 주력 모델을 우선 사용하여 응답 지연을 최소화합니다.
- **설계 원칙:** 고급 모드는 프리셋 파라미터의 부분집합만 노출합니다. 사용자가 임의의 모델 ID나 검증되지 않은 조합을 수동 입력하거나 양자화 파라미터를 계산할 필요가 없습니다.

## 5. 성능 비교 및 평가 방법론

### 5.1 비교 실험군 (4개 군 대조 분석)
- **군 A (단일 고성능 모델 고정):** 단일 에이전트에 플래그십 모델(`anthropic/claude-sonnet-4.5`)만 고정 사용합니다.
- **군 B (단일 에이전트 + 단계별 라우팅):** 단일 에이전트 내에서 작업 단계별로 모델을 전환합니다.
- **군 C (동일 모델 멀티에이전트):** 멀티에이전트 구조이나 모든 에이전트가 동일 고성능 모델을 사용합니다. Track 2 고정 파이프라인의 효과를 모델 구성과 분리하기 위한 대조군입니다.
- **군 D (제안 시스템):** 단일 배포형 통합 앱 + 하드웨어 적응형 4-Tier 로컬 실행(Tier 0~3) + 2-Track 파이프라인 + JevBench 고정 결정 프리셋 5종(`baseten/mammoth-1`, `openrouter/drex-max`, `openrouter/subq-snap-1.1`, `openrouter/d1-ultra`, `openrouter/elephant-9b`) + 주력 코드 생성 `deepseek/deepseek-v4.1-flash-1017`, 폴백 `deepseek/deepseek-chat-v3.1`, 플래그십 승격 `anthropic/claude-sonnet-4.5` 구성입니다.
- *(참고군)* **ChatGPT Plus 기반 Codex:** 월 USD 20 정액제 환경과의 체감 비용 및 성공률을 대조합니다(공식 API 정가 환산치와 실제 구독료를 분리하여 한계를 명시).

> **비교 설계 유의:** 런타임 이기종 자동 배치 군은 본 실험에서 제외합니다. 해당 방식은 §1.3에 따라 채택하지 않았으며, 검증되지 않은 라우팅 정책을 기준선으로 두면 군 D의 개선 효과가 라우팅 품질 차이에 가려지기 때문입니다. 대신 프리셋 고정·하드웨어 4-Tier·2-Track·토큰 최적화의 기여를 ablation으로 분리합니다.

**대조의 공정성 확보:** 군 A~D는 동일 저장소, 동일 과제 세트, 동일 검증 스크립트를 사용합니다. 군 D의 우위는 모델 자체가 아니라 **프리셋 고정 + 4-Tier 로컬 실행 + 2-Track 실행 + 토큰 최적화**에서 발생해야 하며, 이를 분리하기 위해 아래 절제(ablation) 실험을 병행합니다.

- **Ablation D-1 (프리셋 및 로컬 티어 제거):** 군 D에서 프리셋과 로컬 온디바이스 티어를 제거하고 매 요청마다 플래그십 클라우드를 강제하여, 비용 절감분이 프리셋 및 로컬 티어에서 오는지 확인합니다.
- **Ablation D-2 (2-Track 제거):** 모든 작업을 Track 2로 처리하여, Track 1의 계획 오버헤드 제거 효과를 분리 측정합니다.
- **Ablation D-3 (토큰 최적화 제거):** AST 슬라이싱과 FTS5 검색을 비활성화하여 컨텍스트 절감 기여도를 측정합니다.
- **Ablation D-4 (하드웨어 티어링 효과):** 로컬 티어(Tier 1~3)를 비활성화하고 순수 클라우드만 사용할 때와 대비하여, 로컬 온디바이스 연산의 비용(USD 0 절감) 및 응답 지연 단축 기여도를 실측합니다.

## 9. 결론

본 작품은 **DeepSeek Harness 실행 코어**에 **OpenCodex 기반 모델 게이트웨이를 내장한 단일 배포형 통합 애플리케이션**입니다. 별도 중앙 서버 없이 설치만으로 완결되는 구조는 경진대회 프로토타입과 1인·소규모 개발 팀에게 가장 현실적인 배포 형태입니다.

런타임에 신규 모델을 탐색·분류하거나 작업마다 이기종 서브에이전트를 자동 배치하는 대신, 개발자가 Benchmark Heaven JevBench 결과 기반으로 오프라인 검증한 고정 결정 모델 프리셋 5종(`baseten/mammoth-1` 주 결정, `openrouter/drex-max`, `openrouter/subq-snap-1.1`, `openrouter/d1-ultra`, `openrouter/elephant-9b`)과 주력 코드 생성 모델(`deepseek/deepseek-v4.1-flash-1017`), 플래그십 승격 모델(`anthropic/claude-sonnet-4.5`)을 주기적 앱 업데이트로 배포합니다. 이 결정은 런타임 라우팅의 불확실성과 미검증 모델의 환각 위험을 제거하고, 마감 전 구현 난이도를 통제하며, 모든 사용자에게 일관된 경험을 보장합니다.

특히 본 작품은 **PC 하드웨어 사양을 자동 진단하여 순수 규칙/클라우드(Tier 0)부터 온디바이스 GGUF 및 3진수 고속 가속(Tier 1~3: Tier 1~2 GGUF Q4_K_M, Tier 3 Prism ML Bonsai 2 27B / 32B GGUF)까지 확정하는 4-Tier 적응형 로컬 실행 아키텍처(Tier 0 순수 규칙/클라우드 → Tier 1 1.5B/3B GGUF → Tier 2 7B/8B GGUF → Tier 3 27B/32B 플래그십 가속 노드)**를 완벽 구현하였습니다. 이를 통해 일반 사무용 저사양 노트북부터 RTX 4090 기반 고성능 가속 노드까지 차별 없이 동작하며, 로컬 처리 가능 작업은 API 비용 USD 0 및 완벽한 코드 프라이버시로 완결합니다.

그 위에 Zero-Config(`mode="auto"`), 2-Track 실행 파이프라인, AST 심볼 슬라이싱(70~85% 토큰 절감), SQLite FTS5 무VRAM 검색(5ms), TokenEconomizer, Git worktree/SQLite 스냅샷 격리, Harness² 기반 오프라인 하네스 최적화를 결합하여, 누구나 가장 경제적이고 안전하게 고성능 AI 코딩 에이전트를 사용하는 차세대 자율형 개발 환경을 구현합니다.

요약하면 본 작품의 경쟁력은 **"복잡한 지능을 런타임에 즉석 조립하는 것"이 아니라 "검증된 최적 조합을 개발자가 미리 고정해 배포하고, 로컬 하드웨어 잠재력을 4-Tier 로컬 실행으로 극대화하는 것"**에 있습니다. 이 설계 전환은 신뢰성·재현성·비용 효율성·배포 가능성을 동시에 확보하여, 경진대회 시연과 향후 1인 개발자 대상 제품화 모두에 결정적으로 기여합니다.
